# Spec

## 1. Назначение и границы

**Вклад в North Star.** Модуль не влияет на производственную видимость напрямую, но закрывает контур учёта: С1С видит подготовленные данные и отмечает их обработку, что делает состояние «передано в 1С» прозрачным.

**In scope:**
- Рабочее место С1С: единый список задач TaskForOneC (тип PRODUCTION | TRANSFER) со всеми реквизитами (Р-24).
- Данные для документа «Производство» (на Массу и ГП, включая потребление) из итогов смены.
- Данные для документа «Перемещение» из Перемещений.
- Экспорт CSV.
- Отметка «обработано» вручную.

**Out of scope:**
- Прямая интеграция с 1С (API, обмен) — отсутствует в MVP.
- Создание документов в 1С (выполняется вручную в 1С).

## 2. Глоссарий

- **Подготовленные данные** — структурированный набор данных, достаточный для ручного создания документа в 1С.
- **Документ «Производство»** — документ 1С на Массу и ГП, создаваемый по итогам смены.
- **Документ «Перемещение»** — документ 1С, создаваемый по Перемещению ГП.
- **Отметка «обработано»** — ручная отметка С1С о том, что документ создан в 1С.

## 4. Доменная модель

### 4.1. Сущности

**Задача для 1С (TaskForOneC)** (Р-24)
- `id`, `тип` (PRODUCTION | TRANSFER), `источник_id` (итог смены | Перемещение), `данные` (структурированный набор), `статус` (ожидает | обработано), `обработано_в`, `обработал` (С1С), `последнее_изменение` (дата/время, Р-18).

### 4.2. Статусы

`Ожидает → Обработано` (переход инициирует С1С вручную). Отмена отметки «обработано» (`Обработано → Ожидает`) — только С1С с обязательной причиной (Р-17).

## 5. Сценарии (use cases)

**UC-M12-1. Формирование задачи для 1С.**
- Когда итог смены сформирован (M06) → система создаёт задачу типа PRODUCTION с данными на Массу и ГП, включая потребление (Р-10).
- Когда Перемещение отправлено/подтверждено (M07/M08) → система создаёт задачу типа TRANSFER.

**UC-M12-2. Обработка задачи.**
- Когда С1С открывает рабочее место → видит список задач → открывает задачу → копирует данные → создаёт документ в 1С вручную → возвращается и отмечает «обработано» → система переводит задачу в «Обработано».

**UC-M12-3. Отмена отметки «обработано» (Р-17).**
- Когда С1С ошибочно отметил задачу → открывает задачу → нажимает «Отменить обработку» → указывает обязательную причину → система переводит задачу в «Ожидает» и фиксирует отмену в аудите.

## 6. Бизнес-правила

- **BR-1.** Прямой интеграции с 1С нет; документы создаются вручную. (Этап: Итог смены / Получение на складе ГП.)
- **BR-2.** Документ «Производство» формируется на Массу и ГП. (Этап: Итог смены.)
- **BR-3.** Документ «Перемещение» формируется по Перемещению ГП. (Этап: Транспортировка ГП / Получение на складе ГП.)
- **BR-4.** Отметку «обработано» ставит только С1С. (Этап: сквозной.)
- **BR-5.** Задача в статусе «Обработано» не редактируется. (Этап: сквозной.)
- **BR-6.** Данные «Производства» включают потребление Массы/ПФ (Р-10). (Этап: Итог смены.)
- **BR-7.** Рабочее место С1С — единый список задач TaskForOneC (таблицы со всеми реквизитами) + экспорт CSV по обоим типам (Р-06, Р-24). (Этап: сквозной.)
- **BR-8.** Отмена отметки «обработано» — только С1С с обязательной причиной; отметка информационная, другие модули не затрагивает; каждая отмена — в аудит (Р-17). (Этап: сквозной.)
- **BR-9.** С1С всегда видит актуальную (последнюю) версию данных; в колонке «последнее изменение» — дата/время (Р-18). (Этап: сквозной.)
- **BR-10.** Единая сущность TaskForOneC с типом {PRODUCTION, TRANSFER}; единый список, отметка «обработано»/отмена (Р-17) и CSV-экспорт — по задачам обоих типов (Р-24). (Этап: сквозной.)

## 7. События и уведомления

- **Потребляет:** EV-03 (итог смены → задача «Производство»), EV-04/EV-05/EV-07 (Перемещение → задача «Перемещение»).
- **Генерирует:** не генерирует новых событий; уведомления С1С приходят через EV-03/EV-04/EV-05/EV-07 (см. M09).

## 8. Требования к интерфейсу

- Экран «Рабочее место 1С» — единый список задач с фильтром по типу (таблицы со всеми реквизитами).
- Таблица задачи — структурированные данные (номенклатура, количество, потребление) для копирования + колонка «последнее изменение» (дата/время).
- Кнопка «Экспорт CSV».
- Кнопка «Отметить обработано».
- Кнопка «Отменить обработку» (с обязательной причиной).

## 9. Хронометраж

Не ведётся. Время обработки фиксируется полем `обработано_в`.
