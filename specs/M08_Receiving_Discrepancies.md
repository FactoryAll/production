# Spec

## 1. Назначение и границы

**Вклад в North Star.** Приёмка закрывает цикл: «принято на склад ГП» становится фактом, видимым онлайн. Обработка расхождений гарантирует, что остатки склада ГП отражают согласованное (корректное) количество.

**In scope:**
- Приёмка Перемещения: отметка фактического количества, сохранение.
- Обнаружение расхождений (факт ≠ заявлено).
- Согласование расхождений: НП и УСГП договариваются; НП и/или КСГП корректируют количества.
- Уведомление С1С о создании и подтверждении Перемещения.

**Out of scope:**
- Создание Перемещения (M07).
- Данные для 1С (M12).

## 2. Глоссарий

- **Приёмка** — действие КСГП по фиксации фактического количества по строкам Перемещения.
- **Фактическое количество** — количество, зафиксированное КСГП при приёмке.
- **Расхождение** — ситуация, когда фактическое количество ≠ заявленному хотя бы по одной строке.
- **Согласование** — процесс достижения согласия НП и УСГП о корректном количестве с последующей корректировкой.

## 4. Доменная модель

### 4.1. Сущности

Использует сущности M07 (Перемещение, строка Перемещения). Дополнительно:

**Расхождение (Discrepancy)** [ДОПУЩЕНИЕ: фиксируется на уровне строки]
- `id`, `строка_перемещения_id`, `заявленное_количество`, `фактическое_количество`, `статус` (открыто | согласовано).

### 4.2. Статусная модель

`SUBMITTED → RECEIVED | DISCREPANCY → RECONCILED` (см. 00_System_Overview §3.2). Перемещение в `CANCELLED` (Р-12) — терминальное; приёмка отменённого Перемещения невозможна.

| Переход | Событие | Инициатор | Условие |
|---------|---------|-----------|---------|
| `SUBMITTED → RECEIVED` | Перемещение принято (EV-05) | КСГП | Факт = заявлено по всем строкам |
| `SUBMITTED → DISCREPANCY` | Расхождение обнаружено (EV-06) | КСГП | Факт ≠ заявлено хотя бы по одной строке |
| `DISCREPANCY → RECONCILED` | Расхождение согласовано (EV-07) | НП и/или КСГП | По всем строкам заявленное = фактическому |

## 5. Сценарии (use cases)

**UC-M08-1. Приёмка без расхождений.**
- Когда КСГП открывает Перемещение в `SUBMITTED` → отмечает фактическое количество по строкам → сохраняет → система сравнивает с заявленным → при совпадении переводит в `RECEIVED`, генерирует EV-05, приходует на склад ГП (M05).

**UC-M08-2. Приёмка с расхождением.**
- Когда КСГП сохраняет факт, отличающийся от заявленного → система переводит Перемещение в `DISCREPANCY`, генерирует EV-06, уведомляет НП.

**UC-M08-3. Согласование расхождения.**
- Когда НП получает EV-06 → НП и УСГП договариваются о корректном количестве → НП корректирует заявленное количество и сохраняет, и/или КСГП корректирует фактическое количество и сохраняет → система при равенстве по всем строкам переводит в `RECONCILED`, генерирует EV-07, приходует согласованное количество на склад ГП.

## 6. Бизнес-правила

- **BR-1.** Приёмку выполняет только КСГП. (Этап: Получение на складе ГП.)
- **BR-2.** Расхождение фиксируется при несовпадении факта и заявленного хотя бы по одной строке. (Этап: Получение на складе ГП.)
- **BR-3.** При расхождении НП уведомляется; согласование ведут НП и УСГП. (Этап: Получение на складе ГП.)
- **BR-4.** Перемещение завершается (`RECONCILED`) только при равенстве заявленного и фактического по всем строкам. (Этап: Получение на складе ГП.)
- **BR-5.** На склад ГП приходуется фактическое (согласованное) количество. (Этап: Получение на складе ГП.)
- **BR-6.** Приёмка отменённого (`CANCELLED`) Перемещения невозможна (Р-12). (Этап: Получение на складе ГП.)

## 7. События и уведомления

- **Генерирует:** EV-05 «Перемещение принято», EV-06 «Расхождение обнаружено», EV-07 «Расхождение согласовано».
- **Потребляет:** EV-04 «Перемещение отправлено» (источник Перемещения для приёмки).
- **Уведомляет:** EV-05 → С1С (о подтверждении); EV-06 → НП; EV-07 → С1С (о подтверждении), УСГП.

## 8. Требования к интерфейсу

- Экран «Приёмка» (для КСГП) — список Перемещений в `SUBMITTED`.
- Карточка приёмки — таблица строк: заявленное количество (read-only) + поле фактического количества.
- Блок расхождений — подсветка строк с расхождением.
- Форма согласования — поля корректировки заявленного (НП) и фактического (КСГП) количества.

## 9. Хронометраж

Фиксируются переходы (связь с M10):
- `SUBMITTED → RECEIVED` (время приёмки).
- `SUBMITTED → DISCREPANCY` (время обнаружения расхождения).
- `DISCREPANCY → RECONCILED` (время согласования).

## 10. Критерии приёмки

- [ ] КСГП фиксирует фактическое количество и сохраняет.
- [ ] При совпадении — переход в `RECEIVED`, уведомление С1С.
- [ ] При расхождении — переход в `DISCREPANCY`, уведомление НП.
- [ ] НП и/или КСГП корректируют количества; при равенстве — `RECONCILED`.
- [ ] На склад ГП приходуется согласованное количество.
- [ ] Приёмка отменённого Перемещения невозможна (Р-12).

## 11. Открытые вопросы

1. [ДОПУЩЕНИЕ] Расхождение фиксируется на уровне строки (принято: да).
2. [ДОПУЩЕНИЕ] Роль УСГП — только участие в согласовании, без прав редактирования количеств (принято: да).
3. [ДОПУЩЕНИЕ] Может ли КСГП инициировать корректировку фактического количества без НП (принято: да, в рамках согласования).
