# Spec

## 1. Назначение и границы

**Вклад в North Star.** Итог смены — момент, когда «произведено» становится фактом, видимым онлайн. Отчёт за смену даёт НП и С1С сводную картину производства, а дашборд (M11) отражает итоги в реальном времени.

**In scope:**
- Сохранение итогов смены (из фактов M04).
- Суммирование итогов с остатками Производственного склада (через M05).
- Формирование отчёта за смену: таблица + диаграммы.
- Подготовка данных для С1С (передаётся в M12).

**Out of scope:**
- Внесение факта Оператором (M04).
- Рабочее место С1С и отметка «обработано» (M12).
- Сводный дашборд (M11).

## 2. Глоссарий

- **Итог смены** — агрегированный результат производства за смену по всем РЦ.
- **Отчёт за смену** — документ-представление: таблица итогов + диаграммы.
- **Суммирование с остатками** — операция прибавления итогов к остаткам Производственного склада.

## 4. Доменная модель

### 4.1. Сущности

**Итог смены (ShiftResult)** — агрегат по смене:
- `id`, `смена_id`, `пз_id`, `сформирован_в`.
- `итоги[]` — по РЦ: `рц_id`, `выпуск[]` (номенклатура, категория, количество), `потребление[]` (номенклатура, количество), `брак[]`, `остановки`.

**Отчёт за смену (ShiftReport)** — представление:
- `id`, `итог_смены_id`, `таблица` (данные), `диаграммы` (данные для визуализации), `сформирован_в`.

### 4.2. Статусы

Итог смены формируется автоматически при завершении ПЗ (`COMPLETED`). Отчёт — производное представление, статусов не имеет.

## 5. Сценарии (use cases)

**UC-M06-1. Формирование итога смены.**
- Когда ПЗ переходит в `COMPLETED` (все РЦ внесли факт) → система агрегирует факты в итог смены → суммирует с остатками (M05).

**UC-M06-2. Формирование отчёта.**
- Когда итог смены сформирован → система строит отчёт: таблицу по РЦ/номенклатуре (включая потребление) и диаграммы (Р-08): план/факт по РЦ; структура выпуска Масса/ПФ/ГП; брак по причинам (Парето); остановки по длительности → отчёт доступен НП и С1С.

**UC-M06-3. Просмотр отчёта.**
- Когда НП/С1С открывает отчёт → система показывает таблицу и диаграммы.

## 6. Бизнес-правила

- **BR-1.** Итог смены формируется только после завершения ПЗ (`COMPLETED`). (Этап: Итог смены.)
- **BR-2.** Итоги суммируются с остатками Производственного склада. (Этап: Итог смены.)
- **BR-3.** Отчёт содержит таблицу и диаграммы. (Этап: Итог смены.)
- **BR-4.** Отчёт доступен НП и С1С; Оператор видит только свой РЦ. (Этап: Итог смены.)
- **BR-5.** Состав диаграмм (Р-08): план/факт по РЦ; структура выпуска Масса/ПФ/ГП; брак по причинам (Парето); остановки по длительности. (Этап: Итог смены.)
- **BR-6.** Отчёт включает блок потребления Массы/ПФ (Р-10). (Этап: Итог смены.)
- **BR-7.** Длительности в отчёте агрегируются в формате «чч:мм» (Р-05). (Этап: Итог смены.)

## 7. События и уведомления

- **Потребляет:** EV-03 «Итог смены внесён» (триггер агрегации).
- **Генерирует:** данные для С1С (передаются в M12); уведомление С1С — через EV-03 (см. M09).
- **Уведомляет:** С1С (in-app, переход в отчёт/данные для 1С).

## 8. Требования к интерфейсу

- Экран «Отчёты за смену» — список отчётов по сменам.
- Экран отчёта — таблица (РЦ × номенклатура × количество, включая потребление) + диаграммы (план/факт по РЦ; структура выпуска Масса/ПФ/ГП; брак по причинам; остановки по длительности).
- Фильтр по смене/дате.

## 9. Хронометраж

Фиксируется время завершения ПЗ (`IN_PROGRESS → COMPLETED`) — уже в M03/M10. Дополнительно фиксируется время формирования итога/отчёта [ДОПУЩЕНИЕ].

## 10. Критерии приёмки

- [ ] Итоги суммируются с остатками Производственного склада.

- [ ] С1С получает уведомление и данные.
