# Spec

## 1. Назначение и границы

**Вклад в North Star.** Уведомления — механизм, который «приводит» пользователя к актуальным данным в нужный момент: Оператор узнаёт о ПЗ, КСГП — о Перемещении, С1С — о готовых данных. Это обеспечивает своевременную онлайн-видимость и реакцию.

**In scope:**
- Генерация уведомлений по каталогу событий (00_System_Overview §5).
- Центр уведомлений (список, фильтр по прочитанности, сортировка).
- Кликабельные переходы (deep-link) в целевой модуль/документ.
- Состояние прочитанности.

**Out of scope:**
- Email, мессенджеры, внешние системы (запрещено).
- Бизнес-логика документов (M03–M08).

## 2. Глоссарий

- **Уведомление** — in-app сообщение пользователю о событии, с переходом к целевому объекту.
- **Центр уведомлений** — экран со списком уведомлений пользователя.
- **Прочитанность** — состояние уведомления: «непрочитано» / «прочитано».
- **Deep-link (переход)** — целевая ссылка на модуль/таблицу/документ.

## 3. Роли и права

| Действие | НП | ОПР | КСГП | УСГП | С1С | АДМ |
|----------|----|-----|------|------|-----|-----|
| Просмотр своих уведомлений | R | R | R | R | R | R |
| Отметка прочитанным | X | X | X | X | X | X |

> Уведомления адресуются ролям/пользователям согласно каталогу событий; пользователь видит только свои уведомления.

## 4. Доменная модель

### 4.1. Сущности

**Уведомление (Notification)**
- `id`, `событие_код` (EV-xx), `получатель_id` (пользователь), `заголовок`, `текст`, `deep_link` (модуль/документ), `прочитано` (bool), `создано_в`, `прочитано_в`.

### 4.2. Статусы

Уведомление: `Непрочитано → Прочитано` (переход при открытии/переходе по уведомлению).

## 5. Сценарии (use cases)

**UC-M09-1. Генерация уведомления.**
- Когда происходит событие из каталога → система создаёт уведомления для получателей согласно каталогу → уведомления появляются в центре уведомлений.

**UC-M09-2. Просмотр и переход.**
- Когда пользователь открывает центр уведомлений → система показывает список (непрочитанные сверху) → пользователь кликает уведомление → система открывает целевой модуль/документ и помечает уведомление прочитанным.

**UC-M09-3. Отметка прочитанным.**
- Когда пользователь открывает уведомление → система помечает его прочитанным и фиксирует время.

## 6. Бизнес-правила

- **BR-1.** Уведомления — только in-app. (Этап: сквозной.)
- **BR-2.** Каждое уведомление кликабельно и ведёт в целевой модуль/документ. (Этап: сквозной.)
- **BR-3.** Уведомление адресуется получателям согласно каталогу событий. (Этап: сквозной.)
- **BR-4.** Прочитанность фиксируется при открытии/переходе. (Этап: сквозной.)
- **BR-5.** Пользователь видит только свои уведомления. (Этап: сквозной.)

## 7. События и уведомления

Модуль — потребитель всех событий каталога (EV-01…EV-10) и генератор уведомлений. Сводка (источник истины — 00_System_Overview §5):

| Событие | Получатели | Переход |
|---------|-----------|---------|
| EV-01 ПЗ подтверждено | Операторы РЦ | Карточка ПЗ (M03) |
| EV-02 Получение ПЗ подтверждено | НП | Карточка ПЗ (M03/M04) |
| EV-03 Итог смены внесён | С1С | Отчёт/данные для 1С (M06/M12) |
| EV-04 Перемещение отправлено | КСГП, С1С | Карточка Перемещения (M07) |
| EV-05 Перемещение принято | С1С | Карточка Перемещения (M08) |
| EV-06 Расхождение обнаружено | НП | Карточка Перемещения (M08) |
| EV-07 Расхождение согласовано | С1С, УСГП | Карточка Перемещения (M08) |
| EV-08 Смена закрыта за Оператора | Оператор РЦ, С1С | Карточка ПЗ, строка РЦ (M03/M04) |
| EV-09 ПЗ отменено | Операторы назначенных РЦ | Карточка ПЗ (M03) |
| EV-10 Перемещение отменено | КСГП, С1С | Карточка Перемещения (M07) |

> Ввод за Оператора (Р-11) дополнительно генерирует EV-03 «Итог смены внесён».

## 8. Требования к интерфейсу

- Индикатор непрочитанных уведомлений (счётчик) в шапке приложения.
- Экран «Уведомления» — список с фильтром «все/непрочитанные/прочитанные», сортировка по времени (новые сверху).
- Каждое уведомление — кликабельная карточка с заголовком, текстом и временем.
- Переход по клику в целевой модуль/документ.

## 9. Хронометраж

Не ведётся. Время создания и прочтения уведомления фиксируется полями `создано_в`/`прочитано_в`.

## 10. Критерии приёмки

- [ ] Все события каталога (EV-01…EV-10) генерируют уведомления нужным получателям.
- [ ] Каждое уведомление кликабельно и ведёт в целевой объект.
- [ ] Прочитанность фиксируется и фильтруется.
- [ ] Нет внешних каналов (email/мессенджеры).
- [ ] Пользователь видит только свои уведомления.
