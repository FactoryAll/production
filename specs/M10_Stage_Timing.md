# Author Note

- **Модуль:** M10 — Хронометраж этапов.
- **Версия/статус:** v1.1 / На согласовании.
- **Этапы ЖЦ:** сквозной (фиксация времени переходов на всех этапах).
- **Зависимости:** 00_System_Overview (принципы хронометража), M03, M04, M07, M08 (источники переходов).
- **Назначение:** фиксация времени статусных переходов ключевых документов (ПЗ и Перемещение) для измерения длительности этапов жизненного цикла.

# Spec

## 1. Назначение и границы

**Вклад в North Star.** Хронометраж даёт временно́е измерение онлайн-видимости: сколько документ «висит» в каждом статусе, какова длительность этапов. Это питает сводный дашборд (M11) и позволяет видеть «возраст» документов.

**In scope:**
- Запись времени статусных переходов ПЗ и строк ПЗ.
- Запись времени статусных переходов Перемещения.
- Предоставление данных о длительности этапов.

**Out of scope:**
- Управление переходами (бизнес-логика модулей).
- Визуализация (M11).

## 2. Глоссарий

- **Хронометраж** — фиксация времени статусных переходов.
- **Запись хронометража** — факт перехода: документ, сущность, «из → в», время, инициатор.
- **Длительность этапа** — разница времени между переходами.

> Записи хронометража создаются автоматически системой; ручного создания нет.

## 4. Доменная модель

### 4.1. Сущности

**Запись хронометража (TimingRecord)**
- `id`, `документ_тип` (ПЗ | Перемещение), `документ_id`, `сущность` (документ | строка), `сущность_id`, `статус_из`, `статус_в`, `время`, `инициатор_роль`, `инициатор_id`.

### 4.2. Статусы

Записи неизменяемы (append-only).

## 5. Сценарии (use cases)

**UC-M10-1. Фиксация перехода.**
- Когда документ/строка меняет статус → система создаёт запись хронометража с временем и инициатором.

**UC-M10-2. Расчёт длительности.**
- Когда требуется длительность этапа → система вычисляет разницу времени между соответствующими записями.

## 6. Бизнес-правила

- **BR-1.** Каждый статусный переход фиксируется записью хронометража. (Этап: сквозной.)
- **BR-2.** Запись содержит время, инициатора, «из → в». (Этап: сквозной.)
- **BR-3.** Записи неизменяемы. (Этап: сквозной.)
- **BR-4.** Фиксируются только переходы из 00_System_Overview §6. (Этап: сквозной.)

## 7. События и уведомления

Модуль не генерирует уведомлений. Потребляет статусные переходы (события EV-01…EV-10) как триггеры записи, включая переходы в `CANCELLED` (Р-12) и ввод за Оператора (Р-11).

## 8. Требования к интерфейсу

- Экран «Хронометраж» — таблица записей с фильтром по документу/типу.
- Отображение длительности этапов по документу.

## 9. Хронометраж

Сам модуль — реализация хронометража. Перечень фиксируемых переходов — 00_System_Overview §6.

## 10. Критерии приёмки

- [ ] Все переходы из 00_System_Overview §6 фиксируются.
- [ ] Записи содержат время и инициатора.
- [ ] Длительность этапов вычисляется корректно.
- [ ] Записи неизменяемы.
