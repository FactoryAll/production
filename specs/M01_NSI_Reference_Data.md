- **Версия/статус:** v1.3 / Утверждён.
- **Этапы ЖЦ:** сквозной (обеспечивает справочные данные для всех этапов).
- **Зависимости:** 00_System_Overview (корневой). Не зависит от других модулей.
- **Назначение:** ведение нормативно-справочной информации — производственные центры (РЦ), сотрудники, номенклатура, причины брака, смены. Является источником справочных данных для всех остальных модулей.

# Spec

## 1. Назначение и границы

**Вклад в North Star.** Справочники задают «словарь» системы: без корректной номенклатуры, РЦ и смен невозможно ни планировать, ни учитывать производство, ни показывать остатки. Корректность НСИ — необходимое условие достоверной онлайн-видимости «что и сколько производится/произведено/перемещается/принято».

**In scope:**
- Справочник производственных центров (РЦ).
- Справочник сотрудников (с привязкой к ролям — см. M02).
- Справочник номенклатуры с категориями (Масса, ГП) и единицами измерения (Р-01).
- Справочник причин брака.
- Справочник причин «ввода за Оператора» (Р-13).
- Справочник смен (2 смены/сутки, привязка к дате).
- Справочник складов (Производственный склад, Склад ГП) — фиксированный из 2 записей (Р-19).

**Out of scope:**
- Назначение ролей и прав (M02).
- Производственные задания и их строки (M03).
- Остатки и их расчёт (M05).
- Любая интеграция с 1С (M12).

## 2. Глоссарий

- **РЦ (производственный центр)** — единица производственной структуры, на которую назначается план и работники в рамках ПЗ.
- **Сотрудник** — физическое лицо, зарегистрированное в системе, которому назначаются роли.
- **Номенклатура** — позиция производимой/учитываемой продукции с категорией и единицей измерения.
- **Категория продукции** — классификатор номенклатуры: Масса, Готовая продукция (ГП). ПФ — не самостоятельная номенклатура, а состояние ГП-позиции, выбираемое при вводе факта (Р-01).
- **Причина брака** — справочное значение, обязательное при фиксации брака.
- **Причина ввода за Оператора** — пресет-лист {болезнь, неявка, ушёл во время смены, прочее} + обязательный свободный комментарий (Р-13).
- **Смена** — временной интервал работы (2 смены в сутки), к которому привязывается ПЗ.
- **Склад** — место хранения остатков: Производственный склад (Масса, ПФ, ГП) и Склад ГП (только ГП).

## 4. Доменная модель

### 4.1. Сущности

**РЦ (WorkCenter)**
- `id`, `наименование`, `код` (уникальный, обязательный, Р-20), `производит_массу` (bool), `active` (bool, Р-21).
- Сид-данные (Р-02): 12 РЦ — 01.Реактор, 02.Миксер, 03.Тубировка крем, 04.Тубировка паста, 05.Линия вязк.прод, 06.Линия жидк.прод, 07.П/авт вязк.прод, 08.П/авт жидк.прод, 09.Ручн налив №1, 10.Ручн налив №2, 11.Ручн налив №3, 12.Ручн налив №4.
- Правило (Р-02): Масса производится только на 01/02 (`производит_массу = true`); номенклатура ГП — только на 03–12.

**Сотрудник (Employee)**
- `id`, `ФИО`, `табельный_номер` (уникальный, обязательный, Р-20), `active` (bool, Р-21).
- Связь с ролями — в M02.

**Номенклатура (Product)**
- `id`, `наименование`, `код` (уникальный, обязательный, Р-20), `категория` (Масса | ГП), `единица_измерения`, `active` (bool, Р-21).
- Правило (Р-01): категория номенклатуры — «Масса» или «ГП». ПФ — не самостоятельная номенклатура, а состояние ГП-позиции, выбираемое Оператором при вводе факта.

**Причина брака (DefectReason)**
- `id`, `наименование`, `active` (bool, Р-21).

**Причина ввода за Оператора (OperatorSubstitutionReason)** (Р-13)
- `id`, `код` (enum: ILLNESS | NO_SHOW | LEFT_SHIFT | OTHER), `наименование`, `active` (bool, Р-21).
- Пресет-лист: болезнь (ILLNESS), неявка (NO_SHOW), ушёл во время смены (LEFT_SHIFT), прочее (OTHER).

**Смена (Shift)**
- `id`, `номер` (1 | 2), `дата`, `время_начала`, `время_окончания`, `active` (bool, Р-21).
- Расписание (Р-05): 1-я смена 08:00–20:00, 2-я смена 20:00–08:00 следующего дня.

**Склад (Warehouse)**
- `id`, `наименование`, `описание`, `тип` (Производственный | Склад ГП), `active` (bool, Р-21).
- Фиксированный справочник из 2 записей (Р-19): Производственный склад, Склад ГП. В MVP добавление/удаление запрещено; АДМ может редактировать только название и описание.

### 4.2. Статусы

Справочники имеют атрибут `active` (bool). Удаление записей запрещено (Р-21) — только деактивация (`active = false`). Деактивированное: недоступно для выбора в новых документах (ПЗ, Перемещения, факты); остаётся видимым в исторических документах и отчётах с пометкой «(неактивно)». State machine: `active = true ↔ false` (переход инициирует АДМ).

## 5. Сценарии (use cases)

**UC-M01-1. Создание номенклатуры.**
- Когда АДМ открывает справочник номенклатуры → нажимает «Создать» → система открывает форму.
- АДМ заполняет наименование, категорию, единицу измерения → сохраняет → система создаёт позицию с `active = true`.
- Альтернатива: категория не из {Масса, ГП} → система блокирует сохранение с сообщением об ошибке.

**UC-M01-2. Деактивация позиции (Р-22).**
- Когда АДМ открывает позицию → нажимает «Деактивировать» → система устанавливает `active = false`.
- Если позиция используется в незавершённых документах → система показывает предупреждение со списком этих документов; деактивация разрешена.
- После деактивации позиция остаётся в незавершённых и исторических документах с пометкой «(неактивно)»; приёмка/ввод факта по ней возможны до закрытия документа; в новых документах недоступна.

**UC-M01-3. Ведение смен.**
- Когда АДМ создаёт смену → указывает номер, дату, время → сохраняет → система создаёт смену.
- Исключение: смена с тем же номером и датой уже существует → система блокирует дубликат.

## 6. Бизнес-правила

- **BR-1.** Категория номенклатуры — одно из: Масса, ГП (Р-01). (Этап: сквозной.)
- **BR-2.** ПФ — не самостоятельная номенклатура, а состояние ГП-позиции, выбираемое при вводе факта (Р-01). (Этап: Производство.)
- **BR-3.** Причина брака обязательна при фиксации брака (используется в M04). (Этап: Производство.)
- **BR-4.** Смена уникальна по паре (номер, дата). (Этап: Планирование.)
- **BR-5.** Неактивные позиции справочников не предлагаются при создании новых документов. (Этап: сквозной.)
- **BR-6.** Склад типа «Склад ГП» может хранить только номенклатуру категории «ГП». (Этап: Получение на складе ГП.)
- **BR-7.** Масса производится только на РЦ 01/02; номенклатура ГП — только на РЦ 03–12 (Р-02). (Этап: Планирование.)
- **BR-8.** Причина ввода за Оператора — из пресета {ILLNESS, NO_SHOW, LEFT_SHIFT, OTHER} + обязательный комментарий (Р-13). (Этап: Производство.)
- **BR-9.** Справочник складов фиксирован из 2 записей; добавление/удаление запрещено, редактируются только название и описание (Р-19). (Этап: сквозной.)
- **BR-10.** `код` номенклатуры и РЦ, `табельный_номер` сотрудника — уникальные и обязательные; валидация при создании и импорте (Р-20). (Этап: сквозной.)
- **BR-11.** Удаление записей справочников запрещено; только деактивация через `active = false` (Р-21). (Этап: сквозной.)
- **BR-12.** Единица измерения потребления = единица измерения потребляемой позиции номенклатуры (Р-14). (Этап: Производство.)
- **BR-13.** Деактивация позиции, используемой в незавершённых документах (Р-22): предупреждение со списком таких документов; деактивация разрешена; позиция остаётся в незавершённых/исторических документах с пометкой «(неактивно)»; приёмка/ввод факта по ней возможны до закрытия; в новых документах недоступна (согласовано с Р-21). (Этап: сквозной.)

## 7. События и уведомления

Модуль M01 не генерирует уведомлений (справочные операции). Изменения справочников фиксируются в аудите (M13).

## 8. Требования к интерфейсу

- Экран «Справочники» — список справочников с переходом в каждый.
- Экран справочника — таблица позиций с поиском, фильтром по активности, действиями «Создать», «Редактировать», «Деактивировать/Активировать».
- Форма позиции — поля согласно доменной модели, валидация по бизнес-правилам.

## 9. Хронометраж

Справочники не имеют статусных переходов жизненного цикла продукции; хронометраж не ведётся. Изменения фиксируются в аудите (M13).

## 10. Критерии приёмки

- [ ] Созданы все справочники: РЦ, сотрудники, номенклатура, причины брака, смены, склады.
- [ ] Номенклатура поддерживает категории Масса/ГП и единицы измерения (Р-01).
- [ ] Сид-РЦ (12) загружены с атрибутом «производит Массу» (Р-02).
- [ ] Смены имеют расписание 08:00–20:00 / 20:00–08:00 (Р-05).
- [ ] Валидация категорий (Масса/ГП) и правила Р-02 (Масса на 01/02, ГП на 03–12) работают.
- [ ] Деактивация позиций не ломает исторические документы.
- [ ] Права доступа соответствуют матрице (только АДМ изменяет справочники).
- [ ] Справочник причин ввода за Оператора с пресетом и комментарием (Р-13).
- [ ] Склады фиксированы (2 записи), удаление/добавление запрещено (Р-19).
- [ ] `код`/`табельный_номер` уникальны и обязательны (Р-20).
- [ ] Удаление запрещено, только деактивация `active = false` (Р-21).
- [ ] Деактивация используемой позиции показывает предупреждение со списком незавершённых документов (Р-22).
