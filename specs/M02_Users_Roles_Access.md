# Spec

## 1. Назначение и границы

**Вклад в North Star.** Онлайн-видимость означает, что каждый пользователь видит ровно то, что ему положено по роли, и в нужный момент. Модуль гарантирует, что Оператор видит свой РЦ, КСГП — свои Перемещения, а НП — весь контур планирования и согласования.

**In scope:**
- Учётные записи пользователей (привязка к сотруднику из M01); создание — только АДМ, без саморегистрации (Р-15).
- Роли: НП, Оператор, КСГП, УСГП, С1С, Администратор.
- Назначение ролей пользователям.
- Сессионная авторизация (без внешних IdP).
- Политика первичного пароля и обязательной смены при первом входе (Р-15).
- Матрица доступа «роль × действие».

**Out of scope:**
- Внешние IdP (OAuth, SSO, LDAP).
- Мультитенантность (одно предприятие).
- Бизнес-логика документов (M03–M08).

## 2. Глоссарий

- **Пользователь** — учётная запись, связанная с сотрудником, через которую выполняется вход.
- **Роль** — именованный набор прав доступа.
- **Право (действие)** — атомарное разрешение на операцию (создание, чтение, изменение, выполнение).
- **Сессия** — состояние аутентифицированного пользователя между входом и выходом.
- **Аутентификация** — проверка подлинности пользователя (логин/пароль).
- **Авторизация** — проверка прав пользователя на действие.

## 4. Доменная модель

### 4.1. Сущности

**Пользователь (User)**
- `id`, `логин`, `пароль` (хэш), `сотрудник_id` (→ M01), `активен` (bool), `must_change_password` (bool, Р-15), `роли[]`.
- Пользователь может иметь несколько ролей (Р-23); итоговые права = объединение прав всех ролей.

**Роль (Role)**
- `id`, `код` (НП | ОПР | КСГП | УСГП | С1С | АДМ), `наименование`, `права[]`.

**Право (Permission)**
- `id`, `код`, `наименование`.

**Сессия (Session)**
- `id`, `пользователь_id`, `создана_в`, `истекает_в`, `активна` (bool).
- Срок жизни сессии — 12 часов (Р-07).

### 4.2. Статусы

Пользователь: `Активен ↔ Заблокирован` (переход инициирует АДМ). Заблокированный пользователь не может войти; активные сессии завершаются.

## 5. Сценарии (use cases)

**UC-M02-1. Вход в систему.**
- Когда пользователь вводит логин/пароль → система проверяет учётную запись → при успехе создаёт сессию (12 ч) и открывает дашборд.
- Альтернатива: неверные данные → система показывает ошибку, сессия не создаётся.
- Исключение: пользователь заблокирован → система отказывает во входе.
- Исключение (Р-07): ОПР вне окна доступа (от −1 ч до начала смены до +1 ч после окончания) → система отказывает во входе.

**UC-M02-2. Назначение роли.**
- Когда АДМ открывает пользователя → назначает роль → сохраняет → система обновляет права пользователя.
- Исключение: снятие последней роли → система предупреждает, что пользователь потеряет доступ.

**UC-M02-3. Выход из системы.**
- Когда пользователь нажимает «Выйти» → система завершает сессию.

**UC-M02-4. Первый вход и смена пароля (Р-15).**
- Когда пользователь с `must_change_password = true` входит → система открывает только экран смены пароля.
- Пользователь вводит новый пароль (≥8 символов, буквы+цифры) → система сохраняет, снимает `must_change_password`, открывает дашборд.
- Исключение: пароль не соответствует требованиям → система блокирует смену; доступ к остальным экранам запрещён до смены.

## 6. Бизнес-правила

- **BR-1.** Пользователь обязан быть привязан к сотруднику из M01. (Этап: сквозной.)
- **BR-2.** Пользователь может иметь несколько ролей; итоговые права = объединение прав ролей (Р-23). (Этап: сквозной.)
- **BR-3.** Доступ к действию предоставляется только через роль; прямых прав вне ролей нет. (Этап: сквозной.)
- **BR-4.** Заблокированный пользователь не может аутентифицироваться. (Этап: сквозной.)
- **BR-5.** Сессия действует 12 часов; по истечении требуется повторный вход (Р-07). (Этап: сквозной.)
- **BR-6.** Только АДМ управляет пользователями и ролями. (Этап: сквозной.)
- **BR-7.** ОПР имеет окно доступа 14 часов: от −1 ч до начала смены до +1 ч после окончания. Вне окна ОПР не может войти и выполнять действия (Р-07). (Этап: Производство.)
- **BR-8.** Саморегистрации нет; пользователей создаёт только АДМ (Р-15). (Этап: сквозной.)
- **BR-9.** Первичный пароль: ≥8 символов, буквы+цифры, выдаётся АДМ; обязательная смена при первом входе; до смены доступен только экран смены пароля (Р-15). (Этап: сквозной.)
- **BR-10.** При нескольких ролях в аудите роль атрибутируется автоматически по типу действия согласно матрице доступа (Р-23). (Этап: сквозной.)

## 7. События и уведомления

Модуль не генерирует бизнес-уведомлений. События входа/выхода и изменения прав фиксируются в аудите (M13).

## 8. Требования к интерфейсу

- Экран входа (логин/пароль).
- Экран смены пароля (при первом входе, `must_change_password = true`).
- Экран «Пользователи» — список с поиском, действиями «Создать», «Редактировать», «Заблокировать/Разблокировать».
- Экран «Роли» — список ролей с составом прав (только чтение для всех, кроме АДМ).
- Форма пользователя — привязка к сотруднику, назначение ролей.

## 9. Хронометраж

Не ведётся (модуль не относится к жизненному циклу продукции). Вход/выход фиксируются в аудите (M13).

## 10. Критерии приёмки

- [ ] Реализованы все 6 ролей с правами согласно матрице.
- [ ] Вход/выход и сессионная авторизация работают (сессия 12 ч, Р-07).
- [ ] ОПР не может войти/действовать вне окна доступа (Р-07).
- [ ] Заблокированный пользователь не может войти.
- [ ] Назначение/снятие ролей доступно только АДМ.
- [ ] Права объединяются при нескольких ролях.
- [ ] Саморегистрации нет; создание — только АДМ (Р-15).
- [ ] Первый вход требует смены пароля; до смены доступен только экран смены (Р-15).
- [ ] Роль в аудите атрибутируется по типу действия (Р-23).
