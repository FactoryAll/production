- **Назначение:** подтверждение Оператором получения ПЗ и внесение факта производства (Масса, ПФ, ГП, брак, остановки) по окончании смены.

# Spec

## 1. Назначение и границы

**Вклад в North Star.** Модуль превращает план в факт: как только Оператор вносит итог, система онлайн показывает «что и сколько произведено». Это ключевой источник данных для остатков (M05) и отчётности (M06).

**In scope:**
- Подтверждение Оператором получения ПЗ для своего РЦ.
- Внесение факта: выпуск (номенклатура + категория + количество) и потребление (номенклатура Масса/ПФ + количество).
- Фиксация брака с обязательной причиной.
- Фиксация количества и суммарной длительности незапланированных остановок.

**Out of scope:**
- Составление/подтверждение ПЗ (M03).
- Суммирование с остатками (M05).
- Формирование отчёта (M06).

## 2. Глоссарий

- **Подтверждение получения ПЗ** — действие Оператора, фиксирующее, что он принял задание для своего РЦ.
- **Факт производства** — внесённые Оператором итоговые данные: выпуск и потребление.
- **Выпуск** — произведённая продукция: номенклатура + категория (Масса/ГП/ПФ) + количество.
- **Потребление** — израсходованные Масса и ПФ: номенклатура + количество (Р-10). Единица измерения потребления = единица измерения потребляемой позиции номенклатуры (Р-14).
- **Брак** — продукция, не соответствующая требованиям; фиксируется с обязательной причиной.
- **Незапланированная остановка** — простой РЦ вне плана; фиксируется количеством и суммарной длительностью (в минутах).

## 4. Доменная модель

### 4.1. Сущности

**Факт производства (ProductionFact)** — привязан к строке ПЗ (РЦ):
- `id`, `строка_пз_id`, `оператор_id`, `внесено_в`.
- `выпуск[]` — позиции: `номенклатура_id`, `категория` (Масса | ГП | ПФ), `количество`. Категория по Р-01: номенклатура «Масса» — всегда «Масса»; номенклатура «ГП» — Оператор выбирает «ГП» или «ПФ».
- `потребление[]` — позиции: `номенклатура_id` (Масса/ПФ), `количество` (Р-10).
- `брак[]` — позиции: `номенклатура_id`, `количество`, `причина_брака_id` (обязательна).
- `остановки` — `количество`, `суммарная_длительность_минут`.

### 4.2. Статусная модель

Статус строки ПЗ: `ASSIGNED → ACCEPTED → REPORTED` (см. 00_System_Overview §3.1, M03).

- `ASSIGNED → ACCEPTED`: событие EV-02, инициатор Оператор.
- `ACCEPTED → REPORTED`: событие EV-03, инициатор Оператор (внесение факта).
- Правило (Р-04): при РЦ > 1 `REPORTED` возможен только после `ACCEPTED`.

## 5. Сценарии (use cases)

**UC-M04-1. Подтверждение получения ПЗ.**
- Когда Оператор получает уведомление EV-01 → открывает ПЗ → нажимает «Подтвердить получение» для своего РЦ → система переводит строку в `ACCEPTED` и генерирует EV-02.

**UC-M04-2. Внесение факта производства.**
- Когда смена окончена → Оператор открывает строку ПЗ → вносит факт: выпуск (номенклатура + категория + количество), потребление (номенклатура Масса/ПФ + количество), брак с причиной, остановки (в минутах) → сохраняет → система переводит строку в `REPORTED` и генерирует EV-03.
- Альтернатива: брак без причины → система блокирует сохранение (BR-1).
- Альтернатива (Р-10): потребление превышает остаток → система показывает предупреждение, но НЕ блокирует сохранение.
- Исключение (Р-04): при РЦ > 1 строка не в `ACCEPTED` → система блокирует внесение факта.

**UC-M04-3. Корректировка факта (Р-18).**
- Когда Оператор корректирует факт до перехода ПЗ в `COMPLETED` → система перезаписывает факт и фиксирует правку в аудите (кто, когда, старое→новое).
- Исключение (Р-18): ПЗ в `COMPLETED` → Оператор не может корректировать; корректировка — только НП через «ввод за Оператора» (Р-11) с причиной и пометкой «корректировка после закрытия».

## 6. Бизнес-правила

- **BR-1.** Брак фиксируется только с указанием причины (обязательное поле). (Этап: Производство.)
- **BR-2.** Категория при вводе факта (Р-01): номенклатура «Масса» — всегда «Масса»; номенклатура «ГП» — Оператор выбирает «ГП» или «ПФ». (Этап: Производство.)
- **BR-3.** Факт вносит только назначенный Оператор своего РЦ. (Этап: Производство.)
- **BR-4.** Остановки фиксируются количеством и суммарной длительностью в минутах (Р-05). (Этап: Производство.)
- **BR-5.** Внесение факта переводит строку в `REPORTED` и генерирует EV-03. (Этап: Производство.)
- **BR-6.** На РЦ, производящем ГП/ПФ, Оператор указывает потреблённые Массу и ПФ; превышение остатка — предупреждение, не блокировка (Р-10). (Этап: Производство.)
- **BR-7.** При РЦ > 1 `REPORTED` возможен только после `ACCEPTED` (Р-04). (Этап: Производство.)
- **BR-8.** Корректировка факта: Оператором — только до `COMPLETED`; после `COMPLETED` — только НП через «ввод за Оператора» с причиной и пометкой «корректировка после закрытия»; каждая правка — в аудит (Р-18). (Этап: Производство/Итог смены.)
- **BR-9.** Единица измерения потребления = единица измерения потребляемой позиции номенклатуры (Р-14). (Этап: Производство.)
- **BR-10.** При вводе за Оператора причина выбирается из пресета + обязательный комментарий (Р-13). (Этап: Производство.)

## 7. События и уведомления

- **Генерирует:** EV-02 «Получение ПЗ подтверждено», EV-03 «Итог смены внесён».
- **Потребляет:** EV-01 «ПЗ подтверждено» (источник доступа Оператора к ПЗ).
- **Уведомляет:** EV-02 → НП; EV-03 → С1С (in-app, переход в отчёт/данные для 1С).

## 8. Требования к интерфейсу

- Экран «Мои задания» (для Оператора) — список строк ПЗ своего РЦ со статусом.
- Форма подтверждения получения — кнопка «Подтвердить получение».
- Форма факта — блок выпуска (номенклатура + категория + количество), блок потребления (номенклатура Масса/ПФ + количество), таблица брака с обязательной причиной, поля остановок (в минутах).
- Валидация: брак без причины не сохраняется.

## 9. Хронометраж

Фиксируются переходы строки ПЗ (связь с M10):
- `ASSIGNED → ACCEPTED` (время подтверждения получения).
- `ACCEPTED → REPORTED` (время внесения итога).

## 10. Критерии приёмки

- [ ] Оператор подтверждает получение ПЗ для своего РЦ.
- [ ] Оператор вносит факт: выпуск (с выбором категории ГП/ПФ), потребление, брак с причиной, остановки (в минутах).
- [ ] Превышение остатка при потреблении даёт предупреждение, не блокировку (Р-10).
- [ ] Брак без причины блокируется.
- [ ] Внесение факта генерирует EV-03 и уведомляет С1С.
- [ ] Оператор видит только свой РЦ.
- [ ] Корректировка факта Оператором — только до COMPLETED; после — только НП (Р-18).
- [ ] Единицы потребления = ЕИ номенклатуры (Р-14).
