- **T-065** — ошибка подтверждения ПЗ не отображалась пользователю;
- **T-067** — белый экран «Application error: a server-side exception has occurred» вместо понятного отказа в доступе.

## Что вошло в релиз

### T-065. Ошибка подтверждения ПЗ видна пользователю
- Обработчик в карточке ПЗ закрывал диалог и **не сохранял** текст ошибки, поэтому при отказе сервера пользователь не видел причину.
- Исправлено: при ошибке диалог остаётся открытым, сообщение выводится в нём. То же исправление применено к списку ПЗ.
- Остальные обработчики карточки ПЗ (отмена, ввод за Оператора, корректировка факта) уже работали корректно — проверено.
- Добавлен компонентный regression-тест (`production-orders/__tests__/order-card-confirm-error.test.tsx`).

### T-067. Понятный экран отказа в доступе
- Прямой переход на страницу, защищённую проверкой прав, ролью без права (например `/transfers/<id>/receive` под НП или УСГП, `/users` под НП) приводил к серверному исключению и белому экрану.
- Добавлено: `components/access-denied.tsx` (экран «Доступ запрещён» с названием действия, перечнем ролей с доступом, требуемым правом и ссылкой на главную) и `lib/auth/page-guard.ts` (`checkPageAccess()` — проверка без выброса исключения).
- Проверки внедрены на страницах: остатки; Перемещения (список, карточка, создание, правка, приёмка, согласование расхождений); ПЗ (список, правка); пользователи (список, создание, правка); роли (список, карточка).
- Проверки прав в функциях загрузки данных **сохранены** — защита в глубину (прямой вызов запроса без проверки страницы по-прежнему отклоняется).
- Добавлены тесты компонента `AccessDenied`.
