# Руководства по процессу разработки

Директория содержит **переносимый набор документов о процессе**: как устроена работа над проектом от получения задачи
до закрытия. Документы не содержат специфики предметной области и модулей — только порядок работы, роли, форматы
взаимодействия и критерии приёмки. Набор можно копировать в следующий аналогичный проект и адаптировать под него.

## Состав набора

| Файл | Этап | Статус |
|------|------|--------|
| `00_workflow_overview.md` | Сквозной каркас: перечень этапов, передаточные артефакты, общие принципы | создан |
| `01_project_initiation.md` | Получение задачи и инициация проекта | ожидается из чата соответствующего этапа |
| `02_specs.md` | Создание спек | ожидается из чата соответствующего этапа |
| `03_phase_execution.md` | Последовательное выполнение фаз | **создан** |
| `04_final_testing.md` | Финальное тестирование | ожидается из чата соответствующего этапа |
| `05_project_closure.md` | Завершение проекта | ожидается из чата соответствующего этапа |
| `01_project_initiation_prompt.md` | Промпт для чата этапа 1 (по нему агент того чата собирает документ этапа) | создан |

## Правило именования

- Имя файла: `NN_краткое_имя.md`, где `NN` — номер этапа из `00_workflow_overview.md` (двузначный, по порядку).
- Один этап — один документ; если по этапу нужно несколько документов, они получают тот же номер с суффиксом:
  `03_phase_execution_manual_testing.md`.
- Документы этапа пишутся по итогам соответствующего этапа работы и кладутся в этот каталог без изменения структуры.
- Если для сбора документа нужен отдельный чат, рядом кладётся промпт для этого чата: `NN_краткое_имя_prompt.md`.
- Специфика проекта (пути, терминология, названия модулей) в эти документы не попадает — она живёт в остальных
  документах проекта.

## Как пользоваться

1. Перед началом этапа прочитать `00_workflow_overview.md` и документ соответствующего этапа.
2. Документ этапа 3 применяется на **каждой** фазе; при необходимости рядом кладутся уточнения конкретной фазы.
3. Для нового проекта: скопировать каталог целиком, адаптировать терминологию и структуру каталогов, оставить принципы и порядок.
4. Пометки «[требуется уточнение]» внутри документов — открытые места; они закрываются по мере накопления опыта.

## Связь с процессными правилами проекта

Нормативные правила конкретного проекта (`process.md`: самопроверка, версионирование, деплой, ручное тестирование,
доставка задач) остаются в проекте. Документы этого каталога описывают **порядок применения** таких правил в диалоге
с владельцем продукта и переносятся между проектами вместе с ними.
