## Часть 1. Подготовка тестовых данных

### 1.1. Пользователи (войти как admin/admin123 → /users)

Создать/проверить пользователей с ролями:

| Логин | Роль | Полное наименование роли |
|-------|------|--------------------------|
| `np` | NP | Начальник производства |
| `ksgp` | KSGP | Кладовщик склада ГП |
| `usgp` | USGP | Учётчик склада ГП |

> При создании `mustChangePassword = true` (система автоматически).
> Пароль по умолчанию для новых пользователей — совпадает с логином.

### 1.2. Остатки ГП на Производственном складе

Убедиться, что на Производственном складе есть остаток ГП (категория GP). Если нет — выполнить сценарий из Фазы 2:

1. Войти как `np`, создать ПЗ с 1 строкой: РЦ `03.Фасовка`, номенклатура GP, количество `100`.
2. Подтвердить ПЗ.
3. Войти как Оператор РЦ `03`, подтвердить получение, внести итог (выпуск `100`, категория GP).
4. ПЗ закроется автоматически (`COMPLETED`).
5. Проверить `/stock`: Производственный склад должен содержать остаток GP ≈ `100`.

## Часть 2. План ручного тестирования

### Сценарий 1: Создание и отправка Перемещения (M07)

| Шаг | Действие | Ожидаемый результат | Скриншот |
|-----|----------|---------------------|----------|
| 1.1 | Открыть https://prodtracker.factoryall.ru/login, войти как `np`/`np` (сменить пароль при первом входе) | Доступ к `/transfers`, версия в футере `v1.1.0` | |
| 1.2 | Перейти на `/transfers`, нажать «Создать перемещение». Заполнить: Склад-источник — Производственный, Склад-приёмник — Склад ГП. Строка 1: продукт GP (например, «Готовая продукция А»), количество `50`. Строка 2: продукт GP (например, «Готовая продукция Б»), количество `30`. Сохранить | Перемещение создано, статус `DRAFT`, 2 строки | |
| 1.3 | В карточке Перемещения нажать «Отправить», подтвердить в диалоге | Статус `SUBMITTED`, остатки ГП на Производственном складе уменьшились (проверить `/stock`), уведомление EV-04 создано | |

### Сценарий 2: Приёмка без расхождений (M08)

| Шаг | Действие | Ожидаемый результат | Скриншот |
|-----|----------|---------------------|----------|
| 2.1 | Войти как `np`, создать Перемещение с 1 строкой: продукт GP, количество `20`. Отправить | Перемещение `SUBMITTED` | |
| 2.2 | Выйти, войти как `ksgp`/`ksgp` (сменить пароль). Перейти на `/transfers`, открыть Перемещение, нажать «Принять перемещение». В форме приёмки оставить все `actualQuantity = plannedQuantity` (автозаполнено), нажать «Принять» | Статус `RECEIVED`, Discrepancy не созданы, остатки на Складе ГП увеличились (проверить `/stock`), уведомление EV-05 создано | |

### Сценарий 3: Приёмка с расхождениями (M08)

| Шаг | Действие | Ожидаемый результат | Скриншот |
|-----|----------|---------------------|----------|
| 3.1 | Войти как `np`, создать Перемещение с 2 строками: продукт GP «А» количество `40`, продукт GP «Б» количество `30`. Отправить | Перемещение `SUBMITTED` | |
| 3.2 | Войти как `ksgp`, открыть Перемещение, нажать «Принять перемещение». В форме приёмки: Строка 1 — `actualQuantity = 45` (избыток +5), Строка 2 — `actualQuantity = 25` (недостача −5). Нажать «Принять» | Статус `DISCREPANCY`, созданы 2 записи Discrepancy (одна с положительным difference, другая с отрицательным), остатки на Складе ГП увеличились по факту (`45 + 25 = 70`), уведомление EV-06 создано | |

### Сценарий 4: Согласование расхождений (M08)

| Шаг | Действие | Ожидаемый результат | Скриншот |
|-----|----------|---------------------|----------|
| 4.1 | В карточке Перемещения (статус `DISCREPANCY`) нажать «Согласовать расхождения». В форме согласования: Строка 1 (избыток) — `reconciledQuantity = 42` (уменьшение с `45` до `42`), Строка 2 (недостача) — `reconciledQuantity = 28` (увеличение с `25` до `28`). Нажать «Согласовать» | Статус `RECONCILED`, Discrepancy помечены как `reconciled = true`, корректирующие движения применены (`ISSUE` для строки 1, `RECEIPT` для строки 2), остатки на Складе ГП скорректированы, уведомление EV-07 создано | |

## Часть 3. Определение критичности багов

**Critical (хотфикс v1.1.1):**
- Невозможно создать/отправить Перемещение
- Остатки считаются некорректно (списание/возврат)
- Приёмка не фиксирует фактическое количество
- Расхождения не создаются
- Согласование не применяет корректирующие движения
- Блокировка превышения остатка не работает

**Minor (задача в бэклог):**
- UI-проблемы (некритичные баги вёрстки)
- Некритичные предупреждения в консоли
- Улучшения UX
