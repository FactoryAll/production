## Часть 0. Подготовка на VPS (выполняет пользователь)

### 0.1. Деплой релиза

```bash
cd /opt/prodtrack
git fetch origin && git pull origin main
git log -1 --oneline
docker compose down
docker compose build --no-cache
docker compose up -d
sleep 25
bash scripts/postdeploy-check.sh
```

Ожидаемо: сборка завершается без ошибок, скрипт последеплойной проверки проходит,
версия в футере — **v1.3.0** (значение `VERSION` встраивается на этапе сборки, поэтому
обязателен `build --no-cache`).

### 0.2. Миграция и сид

```bash
cd /opt/prodtrack
docker compose exec -T web sh -lc 'prisma migrate deploy --schema=/app/packages/db/prisma/schema.prisma'
docker compose exec -T web sh -lc 'cd /app/packages/db && tsx prisma/seed.ts'
docker compose exec -T web sh -lc 'cd /app/packages/db && tsx prisma/seed.ts'
```

Ожидаемо: применяется миграция `20261006000000_add_task_for_one_c_unique` (уникальный индекс
«одна задача на источник»), оба прогона сида завершаются без ошибок и без дублей.

### 0.3. Проверка соседей по серверу и таблицы задач

```bash
cd /opt/prodtrack
curl -sI https://mes-midex.factoryall.ru || echo "mes-midex DOWN"
curl -sI https://tracker.factoryall.ru || echo "tracker DOWN"
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT indexname FROM pg_indexes WHERE tablename = '\''tasks_for_one_c'\'';"'
```

Ожидаемо: оба соседних сервиса отвечают; среди индексов есть `tasks_for_one_c_type_sourceId_key`.
Вывод прислать — это подтверждает применение миграции к реальной базе.

## Часть 1. Подготовка тестовых данных

### 1.1. Пользователи

| Логин | Роль | Примечание |
|-------|------|------------|
| `admin` | ADM | администратор (пароль из сида) |
| `np` | NP | начальник производства |
| `opr` | OPR | оператор РЦ (привязан к сотруднику-оператору РЦ, производящего ГП) |
| `ksgp` | KSGP | кладовщик склада ГП |
| `s1c` или `test_s1c` | S1C | специалист 1С — основной исполнитель сценариев |

### 1.2. Исходные данные

1. На Производственном складе есть остаток ГП (нужен для сценария 2). Если нет — выполнить короткий цикл Фазы 2 (ПЗ → подтверждение → итог смены).
2. На экране «Роли» (под `admin`) у роли С1С видны права **«Просмотр данных для 1С»** (`onec:read`) и **«Отметка обработано в 1С»** (`onec:process`), у роли АДМ — тоже. Это подтверждает, что сид из шага 0.2 прошёл.
