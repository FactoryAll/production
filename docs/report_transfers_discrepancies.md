# Отчёт «Перемещения и расхождения» — постановка (T-099)

Статус: **постановка**, код не начат. Ждёт ответов главной линии по §7.

Источник: бэклог `tasks.md` T-099 — «перемещения и расхождения: отправлено/принято, суммы
и сроки согласования». Это последний отчёт серии, и единственный, где определение («срок
согласования») в системе отсутствует — поэтому оно не выдумывается, а выводится из данных.

## 1. Зачем

Два вопроса владельца: **сколько идёт перемещение** и **сколько висит расхождение**.
Сейчас ни то, ни другое не видно: доска показывает момент, но не длительность, а расхождения
живут только в карточке перемещения.

## 2. Откуда берутся сроки — проверено по данным, а не по памяти

В схеме нет поля «дата приёмки». Зато есть **журнал переходов статусов**
`StageTiming` (`documentType = GOODS_TRANSFER`), куда пишутся все смены статуса с моментом:
`SUBMITTED` (отправка), `RECEIVED`/`DISCREPANCY` (приёмка), `RECONCILED` (согласование).
Это и есть источник сроков — миграция не нужна.

| Что считаем | От какого события | До какого события | Откуда |
|---|---|---|---|
| Цикл перемещения | `SUBMITTED` | `RECEIVED` / `DISCREPANCY` | `StageTiming.transitionedAt` |
| **Срок согласования** | `DISCREPANCY` (приёмка с расхождением) | `RECONCILED` или «сейчас», если не согласовано | `StageTiming` |
| Возраст незакрытого расхождения | `DISCREPANCY` | текущий момент | `StageTiming` + `now` |

Почему **не** `updatedAt`: это поле меняется любым изменением записи (комментарий, правка
строки), поэтому «дата приёмки» из него после согласования уже не восстановить — ровно та
ловушка, из-за которой правили карточку перемещения (ОПЭ-75). `Discrepancy.reconciledAt` есть,
но он даёт только конец согласования; начало берём из журнала переходов.

### 2.1. Пропуски в журнале — обязательное правило

Журнал заполнялся не всегда: у части исторических документов записи `DISCREPANCY` просто нет.
Тогда:

1. срок согласования показываем **«—»**, а не ноль и не приблизительную дату;
2. такие строки считаем счётчиком **«строк без записи журнала»** — в подписи под таблицей
   и в CSV (как счётчики старых дублей в T-101/T-098);
3. **дату приёмки из `updatedAt` не восстанавливаем** никогда: это ровно ловушка ОПЭ-75,
   значение смещается от любой правки документа;
4. для отбора по периоду (разрез по расхождениям — по дате приёмки) строка без записи журнала
   остаётся видимой: её период определяется по дате отправки, а отсутствие даты приёмки
   объясняется счётчиком. Так документ не исчезает из отчёта молча — но и не получает
   выдуманную дату.

## 3. Суммы — это количества, а не деньги

В системе нет ни цен, ни стоимости: у номенклатуры есть код, наименование, единица и категория.
Поэтому «суммы» в отчёте — **количества по номенклатуре**, а разные номенклатуры между собой
не складываются (как в T-095 и T-098). Если владельцу нужны денежные суммы, это отдельное
решение с появлением цен в модели, и его нельзя изображать в отчёте.

**Количество берём фактическое, а не плановое** (урок ОПЭ-75): после приёмки показываем
`TransferLine.actualQuantity`; план — отдельной колонкой и только когда он отличается.
Для документов без приёмки фактического нет — показываем план и подписываем это.

## 4. Состав отчёта — два разреза

**Разрез «По перемещениям»** (одна строка — документ или его строка):

| Колонка | Значение |
|---|---|
| Перемещение | короткий id, ссылка на `/transfers/{id}` |
| Дата отправки | из `StageTiming` (`SUBMITTED`) |
| Склады | откуда → куда |
| Номенклатура | код, наименование, единица |
| План | `plannedQuantity` |
| Принято | `actualQuantity` (или «—», если приёмки не было) |
| Статус | как в системе, подписью |
| Цикл, ч | от отправки до приёмки; для непринятых — от отправки до сих пор |

**Разрез «По расхождениям»**:

| Колонка | Значение |
|---|---|
| Перемещение | ссылка на документ |
| Номенклатура | код и наименование |
| План / Принято / Разница | из `Discrepancy` (там же хранится `difference`) |
| Приёмка с расхождением | дата из `StageTiming` |
| Согласовано | дата из `reconciledAt` и `reconciledBy` |
| Срок согласования | от приёмки до согласования (или до сих пор) |

Итоги: сколько перемещений, сколько из них с расхождением, сколько расхождений не согласовано,
самый долгий срок согласования, средний срок по согласованным.

## 5. Период, отменённые и права

- Период — **по дате отправки** (`SUBMITTED`); для разреза по расхождениям — **по дате приёмки**
  (иначе согласование, случившееся в следующем месяце, выпадало бы из отчёта о расхождениях).
  Это два разных отбора на одной странице, и их надо подписать, иначе цифры разойдутся —
  вопрос 3 §7.
- Черновики (`DRAFT`) в отчёт не входят: перемещения ещё не было. Отменённые (`CANCELLED`)
  не входят в разрез по перемещениям; в разрез по расхождениям попадают, если расхождение
  было до отмены, — с пометкой «перемещение отменено».
- Права: `reports:read`.

## 6. Чего отчёт не делает

- не считает деньги (нет цен в модели);
- не оценивает «качество» склада (это разговор, а не отчёт);
- не дублирует T-096 «Движение склада» (там движения и остатки, здесь документы и сроки)
  и T-098 «Потребление» (там списание на производство).

## 7. Вопросы к главной линии — отвечены 01.11.2026

1. Срок согласования — **вариант A**: от приёмки с расхождением до согласования.
2. Норматив — **вариант (а): без норматива**, слово «просрочено» не используем.
3. Период разреза по расхождениям — **по дате приёмки**.
4. Выгрузка — **один файл** с колонкой «Разрез».
5. Дополнение владельца: пропуски журнала → срок «—» + счётчик «строк без записи журнала»
   в подписи и CSV; из `updatedAt` дату приёмки не восстанавливать.

### Исходная формулировка вопросов

1. **Определение «срока согласования»:** от **приёмки с расхождением** до согласования
   (рекомендую — измеряет именно согласование) или от **отправки** до согласования
   (включает время в пути, «сколько документ шёл до закрытия»)?
2. **Норматив срока:** норматив в системе не задан нигде, и брать его из воздуха нельзя.
   Варианты:
   - **(а) без норматива** (рекомендую): показываем длительность, сортируем по убыванию,
     слова «просрочено» не используем — правило появится только когда владелец назовёт срок;
   - **(б) норматив-константа** в модуле (как `OVERDUE_AFTER_DAYS = 2` в ОПЭ-60) — тогда нужно
     значение от владельца и появляется колонка «просрочено»;
   - **(в) норматив «в рамках смены приёмки»** — согласовать до конца смены: даёт «просрочено»
     без нового числа, но опирается на расписание смен, а не на решение о сроках.
3. **Период для разреза по расхождениям** — по дате приёмки (рекомендую) или тот же, что
   у перемещений (по отправке)? Если оставить один период, расхождение, согласованное
   в следующем месяце, выпадет из отчёта.
4. **Выгрузка:** один файл с колонкой «Разрез» (как в T-097/T-098) или два файла, потому что
   разрезы разные по смыслу? Рекомендую один файл — привычнее и фильтруется в Excel.

## 9. Проверяемые свойства (пойдут в тесты)

1. Срок согласования считается от `DISCREPANCY` до `RECONCILED` по `StageTiming`, а не по
   `updatedAt`; после правки комментария к строке значение не меняется (в этом и смысл).
1а. **Перемещение с расхождением без записи `DISCREPANCY` в журнале даёт срок «—» и попадает
   в счётчик «строк без записи журнала»** — не ноль и не дату из `updatedAt`.
2. Незакрытое расхождение показывает возраст до текущего момента.
3. Количество — фактическое после приёмки, план — отдельной колонкой (урок ОПЭ-75).
4. Черновик в отчёт не попадает; отменённое с расхождением — попадает с пометкой.
5. Разные номенклатуры не складываются.
6. Перемещение без приёмки не имеет срока согласования (не ноль, а «—»).
