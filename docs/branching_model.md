# Модель веток и стендов ProdTrack

Решение владельца продукта 24.10.2026. **Правила этого документа обязательны к исполнению** —
не рекомендации. Если правило мешает, его меняют явным решением, а не «на этот раз обойдём».

## Три пространства

| Пространство | Ветка | Порт | Домен | Назначение |
|---|---|---|---|---|
| **Прод** | `main` | 3000 | `prodtracker.factoryall.ru` | релиз, которым пользуются люди |
| **Дев** | `dev` | 3001 | `prodtracker-dev.factoryall.ru` | сложные сценарии и фичи, требующие много времени |
| **Фикс** | `fix/*` от `main` | 3002 | `prodtracker-fix.factoryall.ru` | мелкие правки: ошибки, баги, небольшие улучшения — на 1–2 дня |

Ветки — главное, стенды — следствие: стенд существует, чтобы проверить ветку, а не наоборот.

## Обязательные правила

### 1. Миграции создаются только в `main`

Это самое важное правило: разъехавшиеся истории миграций чинятся часами.

- Ветки `dev` и `fix/*` **не создают** файлов в `packages/db/prisma/migrations/`.
- Нужна миграция — она делается в `main`, затем `dev` и активная `fix/*` делают rebase на `main`.
- Если миграция уже есть на `dev` и не готова к `main` — это признак, что работа не «фикс» и не
  готова к релизу: она остаётся на деве, а фикс от неё не зависит.

### 2. Фикс живёт не дольше двух дней

Дольше — это уже фича, ей место в `dev`. Ветка `fix/*` не должна накапливать изменения:
чем дольше она живёт, тем дороже rebase и тем больше шансов разойтись с `dev`.

### 3. Результат фикса уходит и в прод, и в дев

Порядок строго такой:

1. `fix/*` от `main`, правка, тест, пайплайн.
2. Проверка на **фикс-стенде** (`bash scripts/postdeploy-check.sh --fix`).
3. Слияние в `main` → развёртывание прода.
4. `main` → `dev` (merge, не «потом как-нибудь»). Дев не должен отставать от исправлений.

### 4. Ни одна правка не едет на прод без проверки на стенде

- обычная работа: дев → прод;
- мелкий фикс: фикс → прод;
- исключений нет, даже для «одной строчки».

### 5. Стенды дев и фикс закрыты списком разрешённых адресов

Стенд — не для пользователей: вход туда открыт только владельцу и разработчику.
Список — в `/etc/nginx/snippets/prodtracker-<стенд>-allow.conf`. Правило проверяется
автоматически: раздел 9 в `scripts/postdeploy-check.sh`.

### 6. Данные стендов не пересекаются

У каждого стенда своя база и свой `.env`: `.env` (прод), `.env.dev`, `.env.fix`.
Пароли и секреты свои — продовые значения на стендах запрещены.

### 7. Сборки не параллелятся

Один деплой за раз. Две одновременные сборки на 8 ГБ памяти упираются в потолок,
и первым падает то, что случайно оказалось самым большим (проверено 24.10.2026 на 4 ГБ).

## Рабочий цикл

**Мелкий фикс:**

```bash
git checkout main && git pull
git checkout -b fix/короткое-имя
# правка + тест, который падает без неё
pnpm typecheck && pnpm lint && pnpm test && pnpm build
git push origin fix/короткое-имя
# на сервере: checkout ветки, сборка фикс-стенда, проверка
bash scripts/postdeploy-check.sh --fix
# после проверки владельцем: merge в main, прод, затем main -> dev
```

**Долгая фича:**

```bash
git checkout dev && git pull
git rebase main          # перед началом: дев не должен отставать
# работа, ветка dev, проверка на дев-стенде
bash scripts/postdeploy-check.sh --dev
```

## Что нужно сделать один раз (установка третьего стенда)

1. DNS: A-запись `prodtracker-fix.factoryall.ru` → IP сервера.
2. `bash scripts/make-dev-env.sh --fix` — создаёт `.env.fix` со своими секретами.
3. `docker compose -f docker-compose.fix.yml build && docker compose -f docker-compose.fix.yml up -d`
4. nginx: `docs/nginx/prodtracker-fix.factoryall.ru.conf` → `/etc/nginx/sites-available/`, симлинк
   в `sites-enabled`, сертификат `certbot --nginx -d prodtracker-fix.factoryall.ru`.
5. Список разрешённых адресов: `/etc/nginx/snippets/prodtracker-fix-allow.conf` — по образцу
   `prodtracker-dev-allow.conf`.
6. Проверка: `bash scripts/postdeploy-check.sh --fix` — все разделы зелёные.

## Ресурсы сервера

С 24.10.2026: **4 ядра / 8 ГБ памяти / 60 ГБ диска / swap 1 ГБ** — этого хватает на три стенда
и одну сборку. Еженедельная чистка кэша сборки стоит в cron (иначе он дорастает до 20 ГБ
и диск кончается — проверено).
