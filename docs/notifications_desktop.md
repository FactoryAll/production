# Уведомления поверх окон и звук — уровень 1

Решение владельца 01.11.2026. Уровень 2 (сервис-воркеры и Web Push) отложен и здесь **не
делается**: всё работает, пока вкладка открыта, даже если она неактивна.

## 1. Зачем

Пользователи работают в других приложениях, трекер открыт но неактивен — новые уведомления
проходят мимо. Уровень 1 даёт три вещи: **системное окно** на рабочем столе, **звук** и
**одно соединение** канала на всё приложение.

## 2. Одно соединение вместо двух

До правки SSE-канал открывали два места: счётчик в шапке (`unread-badge`) и страница
`/notifications`. На странице уведомлений висели два `EventSource` на одного пользователя.

Теперь канал один — `lib/notifications/stream-client.ts`: модуль держит единственное соединение,
раздаёт кадры подписчикам и закрывает соединение, когда не осталось ни одного. Подписчики:

| Кто | Зачем |
|---|---|
| `components/notification-bridge.tsx` (шапка) | системное окно и звук |
| `components/unread-badge.tsx` (шапка) | счётчик непрочитанных |
| `app/notifications/_client-page.tsx` | обновление списка |

Проверяется буквально: три подписчика дают одно соединение
(`app/notifications/__tests__/single-channel.test.tsx`).

## 3. Кадр канала

`{ unreadCount, latestId, latest? }`. Поле `latest` — `{ id, title, body, deepLink }` последнего
уведомления: без него системному окну нечего показать. Поле необязательное — старые клиенты его
игнорируют, канал остаётся совместимым.

## 4. Правила показа (не спамить)

1. **Первый кадр молчит.** После подключения кадр описывает текущее состояние, а не новое
   событие: если показать его, пользователь получил бы уведомление о том, что уже видел.
2. **Один id — одно окно.** Повторный кадр с тем же `latestId` — тишина; `tag: id` дополнительно
   склеивает окна в системе.
3. **Скрытая вкладка молчит.** Пока `document.hidden`, мост только запоминает новый id. При
   возврате ничего не вываливается пачкой — требования «не показывать пачку при возврате»
   и «не показывать при неактивной вкладке» выполняются одним условием.
4. **Разрешение — по действию.** Кнопка «Включить уведомления» в шапке, видна при
   `Notification.permission === 'default'`. На загрузке страницы разрешение не спрашивается
   никогда. При `denied` показывается подпись, что уведомления запрещены в браузере.
5. **Клик** — `window.focus()` и переход по `deepLink` (без ссылки — в центр уведомлений).

## 5. Настройки

Экрана профиля нет, поэтому настройки живут в браузере: `localStorage['prodtrack.notifications']`
= `{ desktop, sound }`. Сервер о них не знает — это предпочтение устройства. Значения по
умолчанию: **оба выключены** (ничего не происходит без ведома пользователя). Переключатели
в панели рядом с колокольчиком.

## 6. Звук

Осциллятор 0.15 с с затуханием, файла нет. Браузеры блокируют автоплей до первого действия,
поэтому:

- `AudioContext` создаётся только по действию пользователя (включение звука в панели);
- если контекст в состоянии `suspended`, сигнал **не играет** — лучше тишина, чем ошибка
  в консоли;
- контекст создаётся один раз на приложение.

## 7. Деградация

Нет `EventSource` — канал не открывается, остальное приложение работает. Нет `Notification` —
кнопка не рисуется. Нет `AudioContext` — звук выключен молча. Битое `localStorage` — настройки
по умолчанию. Все три случая закреплены тестами.

## 8. Что проверяют тесты

- мост: первый кадр молчит; новый id — одно уведомление; повтор того же id — тишина;
  выключенный переключатель — тишина; скрытая вкладка — тишина и без пачки при возврате;
  звук только при включённом переключателе; переключатель «будит» Web Audio;
- модуль рабочего стола: без разрешения окно не создаётся; клик — фокус и переход по `deepLink`;
  без ссылки — в `/notifications`; `tag = id`;
- настройки: по умолчанию выключено; чтение/запись; битое хранилище → значения по умолчанию;
- звук: до подготовки молчит; 0.15 с; в `suspended` не шумит; контекст один; ошибка создания
  не ломает приложение;
- канал: три подписчика — одно соединение, кадр доходит до всех, после размонтирования
  соединение закрывается.
