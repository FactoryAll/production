## Правила разработки

1. **Спеки — источник истины.** Код строго соответствует `specs/` (v1.3). Любое отклонение оформляется как «предложение изменения спека» и применяется только после согласования с пользователем.
2. **DoD задачи:** код по спеку (BR/UC); unit-тесты на затронутые BR; миграция (если есть) применяется на пустой БД; нет N+1 и лишних запросов; UI на токенах `packages/ui`; коммит ссылается на задачу и BR.
3. **Перед каждым коммитом:** `pnpm typecheck && pnpm lint && pnpm test && pnpm build` — все exit 0. Красное не коммитить.
4. **Версионирование (ПРОЦ-02):** SemVer. Patch (`Z+1`) — хотфиксы критичных багов; **minor (`Y+1`) — завершение фазы, для Фазы 4 это `v1.2.0`**. Тег ставится на `main`. Версия в футере берётся из `docker-compose.yml` (build arg `VERSION` + переменная окружения) — при выпуске релиза её нужно поднять там и в `.env.example`.
5. **Доставка:** короткие осмысленные коммиты в `main` + `git push` (практика наших чатов). Формальный PR-флоу из `process.md` §5 (ветка → PR → зелёный CI → merge) сейчас не используется: если нужно переключиться — уточни у пользователя.
6. **Локальная БД недоступна** (peer-auth, нет sudo), поэтому проверить runtime можно только unit-тестами, typecheck и build. Ошибки времени выполнения ловятся на VPS. Не утверждать, что что-то проверено вживую, если это не так.
7. **Ручное тестирование выполняет пользователь.** Агент не проходит сценарии сам: он готовит план, задания и фиксирует результаты.

## Правила коммуникации

- Язык — **русский**.
- **Формат работы:** агент даёт **пошаговые задания** (действие → ожидаемый результат → что прислать), пользователь выполняет и присылает скриншот/текст, затем следующее задание. Двигаемся по шагам до конца сценария.
- **Команды для VPS** агент присылает готовым блоком; пользователь выполняет и возвращает вывод. Агент не имеет доступа к серверу.
- **Дефекты:** критичные (блокируют работу или искажают данные) — исправляем немедленно и выпускаем patch-релиз; некритичные — фиксируем в `tasks.md` (или `docs/postprod_backlog.md`, если вне фаз) и продолжаем.
- **Отчёты** — по форматам `process.md` §6: самопроверка фазы (`docs/phase_4_selfcheck_report.md`), релиз-отчёт (`docs/release_v1.2.0_report.md`), отчёт о ручном тестировании (`docs/release_v1.2.0_test_report.md`).
- Перед утверждением о содержимом файла — **прочитать файл**. При неясности — задать вопрос, не догадываться.

## Редеплой на VPS (проверенная процедура)

Команды отправлять пользователю **именно в таком виде**:

```bash
cd /opt/prodtrack
git pull origin main
git log -1 --oneline
docker compose down
docker compose build --no-cache
docker compose up -d
sleep 20
docker compose logs --tail=10 web
```

Особенности:

1. Версия в футере задаётся в `docker-compose.yml` (`VERSION`), а не git-тегом — перед релизом поднять значение и пересобрать.
2. `docker build .` из корня **не работает** — Dockerfile лежит в `apps/web/Dockerfile`, сборка только через `docker compose`.
3. `docker compose down` **удаляет логи** контейнера: если разбираем ошибку — снять `docker compose logs --tail=50 web` **до** перезапуска (или использовать `docker compose restart`).
4. `scripts/deploy.sh` может не иметь бита выполнения → `bash scripts/deploy.sh`. Скрипт дополнительно делает `prisma migrate deploy` и идемпотентный `pnpm db:seed`.
5. Сервер общий (соседи: `mes-midex.factoryall.ru`, `tracker.factoryall.ru`) — ничего лишнего не трогать, после деплоя проверять их доступность.
6. Права проверяются кодом (`packages/contracts`), поэтому сид на работоспособность не влияет — он нужен только чтобы новые коды прав отображались на экране «Роли».

**Уроки критичных багов — не повторять:**

1. **Нельзя экспортировать синхронные хелперы из файлов с `'use server'`** — они становятся *Server Reference*, и вызов во время рендера падает с «Server Functions cannot be called during initial render» (это дало 500 + React error #482 на `/transfers`). Хелперы/константы/типы — только в обычные модули (пример: `apps/web/src/app/transfers/labels.ts`).
2. **Запросы данных не держать в `'use server'`-файлах** (пример: `apps/web/src/app/transfers/queries.ts`); из auth-утилит (`lib/auth/session.ts`, `access.ts`, `login.ts`, `session-token.ts`, `require-shift-window.ts`) директива `'use server'` убрана намеренно.
3. **Обработчики клиентских действий обязаны показывать ошибку:** не закрывать диалог до установки ошибки, иначе пользователь видит «ничего не происходит» (исправлено в `transfers/[id]/_client-card.tsx`, `transfers/_client-page.tsx`, `production-orders/[id]/_client-card.tsx`, `production-orders/_client-page.tsx`).
4. **Любая страница под проверкой прав** должна отдавать экран «Доступ запрещён» (`components/access-denied.tsx` + `lib/auth/page-guard.ts`), а не 500.
5. **Лендинг и меню — ролевые:** `lib/auth/landing.ts`, `components/nav-items.ts` (иначе роль без `production_order:read` попадала на падающую страницу).
6. **`startTransition` не использовать с async-функциями** — обычный `async/await` + `useState(isPending)`.
