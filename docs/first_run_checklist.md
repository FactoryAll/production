# Первый запуск на пустой базе: что заполнить и в каком порядке

> Прод: https://prodtrack.vegas-ai.ru. База создана заново 11.11.2026 — в ней только
> справочники из сида и администратор. Этот документ — порядок заполнения, при котором
> ничего не придётся переделывать.

## Что уже есть после сида (заполнять не нужно)

| Справочник | Содержимое |
|---|---|
| Рабочие центры | 13 штук, коды `01`…`13`: Реактор, Миксер, Тубировка крем/паста, линии вязких/жидких, полуавтоматы, ручной налив №1–4, Маркировка ЧЗ |
| Склады | «Производственный» (сырьё и материалы) и «Склад ГП» |
| Причины брака | Брак A, B, C |
| Причины ввода за Оператора | Болезнь, Неявка, Ушёл смену, Иное |
| Причины неявки | Болезнь, Прогул, Отпуск, Отгул за свой счёт, Неявка без объяснения |
| Права и роли | 27 прав, 9 ролей, матрица проверяется тестами |
| Администратор | `admin`, пароль выдан при первом сиде |

Названия РЦ и причины можно переименовать — коды при этом остаются.

## Порядок заполнения

### Шаг 1. Войти и сменить пароль

Логин `admin`, пароль из лога первого сида. Система потребует смену пароля при первом входе —
это не помеха, а требование.

### Шаг 2. Сотрудники (НСИ → Сотрудники)

**Обязательно, иначе производственное задание не создать:** в строке ПЗ оператор обязателен.

| Поле | Что вписать |
|---|---|
| Табельный номер | уникальный (например `001`) |
| ФИО | как в табеле |
| Активен | да |
| Может привлекаться работником РЦ | оставить да, если сотрудник бывает в составе бригады |

### Шаг 3. Пользователи и роли (Администрирование → Пользователи)

Каждому, кто будет работать в системе — своя учётная запись, не общая:

| Кто | Роль | Что увидит |
|---|---|---|
| Начальник производства | `NP` | всё по производству: ПЗ, канбан, отчёты, подтверждение |
| Операторы РЦ | `OPR` | только свои РЦ и свои строки |
| Склад ГП | `KSGP` | перемещения, приёмка, отгрузка |
| Склады | `USGP` | перемещения, приёмка |
| Специалист 1С | `S1C` | задачи 1С, ПЗ на чтение |
| ОТК | `OTK` | просмотр и все отчёты |
| Гость | `GUEST` | только просмотр ПЗ, остатков, перемещений |

Связывать учётную запись с сотрудником **не обязательно** — это нужно только для тех, кто
одновременно и работает в системе, и попадает в табель как оператор.

### Шаг 4. Номенклатура (НСИ → Номенклатура)

Есть импорт из Excel; вручную — по одной позиции. У каждой позиции:

| Поле | Значение и правило |
|---|---|
| Код | уникальный, ≤200 символов. Уникальность проверяется **точным совпадением**: `GP001` и `gp001` — разные коды, система пропустит оба. Держите регистр единым |
| Название | рабочее, как в 1С, ≤200 символов |
| **Категория** | **только `Масса` или `ГП`** — третьего значения в системе нет |
| Единица | обязательна, ≤20 символов, **свободный текст**. «кг» для массы и «шт» для продукции — соглашение, а не проверка: система примет и «л» |
| Активна | да |

**ПФ — не категория номенклатуры.** Полуфабрикат не заводится позицией: он появляется
при вводе факта на ГП-строке и хранится как отдельный остаток. Импорт из Excel такую
попытку ловит и отвечает: «ПФ — не отдельная категория: ПФ указывается при вводе факта
для позиции ГП».

**Правило, из-за которого ПЗ не создастся:** Массу можно планировать только на РЦ `01` и `02`;
на РЦ, который Массу не производит, допустима **только ГП**. Третьей категории нет,
поэтому строку с ПФ поставить нельзя — ПФ не планируется, он вводится фактом.

Импорт: файл не больше **3 МБ** (ограничение сервера — на 889 МБ памяти большая книга
убивает приложение). Если книга больше — делите на части.

### Шаг 5. Смены — заводить не нужно

Экран **НСИ → Смены** работает **только на просмотр**: создавать, править и деактивировать
смены вручную больше не нужно (решение владельца от 06.10.2026).

Смена создаётся сама в момент сохранения ПЗ: в форме ПЗ указываются **дата смены** и **номер**
(1-я или 2-я), по этой паре смена и появляется.

Времена смен зашиты расписанием, выбрать их негде:

| Смена | Время |
|---|---|
| 1-я | 08:00 – 20:00 |
| 2-я | 20:00 – 08:00 (следующих суток) |

**Дата смены — это день НАЧАЛА.** 2-я смена, начавшаяся 31-го в 20:00 и закончившаяся
1-го в 08:00, имеет дату 31-е; в 03:00 1-го числа система считает текущей именно её.

Поэтому первая смена появится вместе с первым ПЗ — и только после этого доска и отчёты
начнут показывать данные: они режут всё по смене.

### Шаг 6. Первое ПЗ (ПЗ → Создать)

Заполнить: **дата смены** и номер, и строки — РЦ, номенклатура, плановое количество, **оператор**.
После сохранения ПЗ нужно **подтвердить** — только тогда оператор увидит его в исполнении.

Два правила, которые срабатывают на первом запуске:

- **Плановое количество — целое и больше нуля.** «150,5» не пройдёт.
- **Дата смены не может быть в прошлом** относительно текущей смены. Вечером это заметно:
  в 20:00–24:00 текущая смена — сегодняшняя, а после полуночи текущей считается вчерашняя
  дата, поэтому «сегодня» становится допустимым только с 08:00.

### Шаг 7. Проверка, что всё связалось

| Где смотреть | Что должно быть |
|---|---|
| Канбан | карточка появилась в «Черновик ПЗ», после подтверждения — в «Подтверждено» |
| Исполнение смены (под оператором) | строка ПЗ видна, можно принять и внести итог |
| Отчёты → Табель | после внесения итога появляется строка со сменой и часами |
| Отчёты → Дисциплина закрытия | незакрытое ПЗ видно и висит |

## Чего нельзя сделать на этом сервере

- **Загружать большие Excel** — лимит 3 МБ, выше приложение не примет.
- **Держать много вкладок** — 889 МБ на два проекта (ProdTrack + MES); при нехватке памяти
  первым пострадает тот, кто потребляет больше.
- **Рассчитывать на бэкапы вне сервера** — их пока нет (открытый риск в `tasks.md`).

## Если что-то не создаётся

Почти всегда причина одна из четырёх: справочник **деактивирован**; у номенклатуры **не та
категория для этого РЦ** (на РЦ 01–02 — Масса, на остальных — ГП); в строке ПЗ **не выбран
оператор**; **количество не целое** или **дата смены в прошлом**. Тексты ошибок в системе
написаны по-русски и называют причину — читайте их буквально.
