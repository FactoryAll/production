# Табель учёта рабочего времени — постановка (T-093)

Статус: **бэклог**, в работу не брать до отдельного решения.
Решение владельца продукта 26.10.2026.

## 1. Зачем

ОТК нужен табель: кто в какие смены работал, кого назначили и кто фактически вышел.
Отчёт входит в раздел «Отчёты» вместе с «Выпуском по РЦ» и «Движением склада»,
но, в отличие от них, требует **доработки данных** — сейчас учёт рабочего времени
в системе не ведётся.

## 2. Чего в системе нет и почему это важно

| Есть | Нет |
|---|---|
| Смены с расписанием (дата, `08:00–20:00`) | Часов работы как отдельного учёта |
| Назначение сотрудников на строку ПЗ (`ProductionOrderLineWorkers`) | Подтверждения, что работник действительно вышел |
| Факт по строке: оператор, выпуск, брак, простои | Фиксации фактического состава работников |
| Переходы этапов (`StageTiming`) | Явки/неявки как отдельного события |

Прямой учёт часов (табельный учёт с табельным номером, видами absence и т.п.) в этой
системе не планируется: владелец решил **учитывать смены**, а не часы.

## 3. Две категории сотрудников

- **Оператор** — один на строку ПЗ (`ProductionOrderLine.operatorId`), вносит итог смены.
- **Работники** — список на строке ПЗ (`ProductionOrderLineWorkers`), назначает НП.
  Поле **необязательное**: строку можно выполнить без работников.

В табеле эти категории учитываются **по-разному** (см. §4 и §5).

## 4. Операторы: по сменам

Три состояния на смену:

| Состояние | Откуда берётся |
|---|---|
| **Назначен** | строка ПЗ этой смены с этим оператором |
| **Отчитался** | по строке внесён факт (`ProductionOrderLineStatus.REPORTED`) — оператором или НП в режиме «за оператора» |
| **Часы по смене** | длительность смены из справочника: `Shift.start` – `Shift.end` (по умолчанию 12 часов) |

### Что такое «пометка расхождений»

Это **визуальный признак в табеле**, а не отдельное событие. Он нужен, чтобы ОТК
сразу видел проблемные клетки, не сверяя столбцы глазами. Три случая:

1. **Назначен, но не отчитался** — оператор был в смене, факта нет. Смена не закрыта.
   Клетка помечается «нет итога».
2. **Отчитался, но не был назначен** — факт внёс НП в режиме «Ввод за Оператора»
   (например, оператор ушёл на больничный). Клетка помечается «введено за оператора» —
   в системе для этого уже есть причина из справочника (`SubstitutionReason`).
3. **Не назначен и не отчитывался** — пустая клетка, ничего не помечается.

Пометки помогают отличить «не работал» от «работал, но не отметился» — это разные
управленческие выводы, и оба видны в одном отчёте.

## 5. Работники: по фактам закрытых строк

Работник считается работавшим в смене, **если он указан в факте закрытой строки**.
Сейчас такого учёта нет — факт хранит только оператора и выпуск.

### Что нужно доработать: подтверждение состава работников при вводе факта

При вводе итога смены оператор должен:

1. увидеть **список назначенных ему работников** (из строки ПЗ), отмеченными;
2. **снять отметку** у тех, кто фактически не выходил;
3. **добавить** тех, кто выходил, но назначен не был;
4. при **любом расхождении** с назначением указать **комментарий с причиной** —
   без него сохранение отклоняется.

Правила:

- если оператор ничего не менял — комментарий не нужен, состав равен назначенному;
- изменения состава фиксируются в аудите: кто изменил, когда, что было и что стало, причина;
- то же действует при **корректировке факта** после закрытия строки;
- поле «Работники» в строке ПЗ остаётся необязательным: можно планировать строку
  вообще без работников, а фактический состав указать при вводе факта.

### Что для этого нужно в данных

Хранить фактический состав работников **на факте**, а не на строке: назначение
(план) и выход (факт) — разные вещи, и после правок назначение меняться не должно.

Предлагаемая модель (обсудить на этапе проектирования):

- новая таблица `ProductionFactWorker`: `productionFactId`, `employeeId`,
  признак «назначен/добавлен», комментарий строки;
- изменения состава — записи в `AuditRecord` (поле `workers`, значения «было → стало»);
- при повторном вводе факта состав берётся из предыдущего факта, чтобы оператор
  не подтверждал одно и то же дважды.

## 6. Из чего складывается табель

Отчёт за период (смена/день/неделя/месяц, несколько месяцев — см. §7):

| Колонка | Оператор | Работник |
|---|---|---|
| Сотрудник | ФИО | ФИО |
| Дата, смена | дата и номер смены | дата и номер смены |
| Роль | Оператор | Работник |
| Назначен | да (если был назначен на строку) | да (если был в плане строки) |
| Факт | «отчитался» / «нет итога» / «за оператора» | «работал» / «не отмечен» |
| Часы | длительность смены | длительность смены |
| Пометка | расхождение (если есть) | расхождение (если есть) |

Итоги за период: смен отработано, часов, число расхождений по сотруднику.

## 7. Период и выгрузка

- Период: **смена, день, неделя, месяц**; месяцы можно выбирать **несколько**.
- Экран + **выгрузка в CSV для Excel** (разделитель `;`, BOM, открывается двойным
  щелчком). Решено владельцем 26.10.2026: `.xlsx` не делаем, чтобы не тянуть
  зависимость ради форматирования.

## 8. Права

- Смотрят: НП, ОТК, АДМ (и С1С, если понадобится — решить при проектировании).
- Гость и остальные — нет.

## 9. Оценка и порядок

Порядок работ:

1. Модель фактического состава работников (`ProductionFactWorker`) + миграция.
2. Ввод факта: подтверждение и правка состава с обязательной причиной (интерфейс + сервер + аудит).
3. Отчёт «Табель»: сборка по трём источникам (назначения, факты, смены).
4. Экран, период, выгрузка.

Оценка: **крупная задача**, сопоставима с модулем. В работе — только после того,
как два первых отчёта («Выпуск по РЦ», «Движение склада») выйдут в прод.

## 10. Открытые вопросы (решить при проектировании)

1. Кто может править состав работников, кроме оператора: НП? С1С? АДМ?
2. Что делать с фактом, если состав меняется после того, как итог уже передан в 1С?
   (Сейчас аналогичная ситуация с количеством решается запретом правки — см. ОПЭ-39.)
3. Учитывать ли работников, назначенных на строку, которая так и не была закрыта:
   в табеле — «назначен, не работал», или не показывать вовсе?
4. Нужен ли отдельный признак «неявка по причине» (болезнь, прогул) для работников,
   или достаточно комментария при снятии отметки?
