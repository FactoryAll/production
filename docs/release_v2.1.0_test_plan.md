## Часть 0. Подготовка на VPS

### 0.1. Деплой релиза

```bash
cd /opt/prodtrack
git fetch origin && git pull origin main
git log -1 --oneline
docker compose down
docker compose build --no-cache
docker compose up -d
sleep 25
bash scripts/postdeploy-check.sh
```

Ожидаемо: сборка без ошибок, проверка зелёная, версия в футере — **v2.1.0**. Миграций в этом релизе нет.

### 0.2. Перенос существующих ПЗ на смены по датам (T-075)

Сначала пробный прогон — он только показывает, что будет сделано:

```bash
cd /opt/prodtrack
docker compose exec -T web sh -lc 'cd /app/packages/db && pnpm exec tsx prisma/backfill-shifts.ts --dry-run'
```

Затем сам перенос:

```bash
docker compose exec -T web sh -lc 'cd /app/packages/db && pnpm exec tsx prisma/backfill-shifts.ts'
```

Ожидаемо: в пробном прогоне — список ПЗ с шаблонной сменой и дата, на которую каждый будет перенесён;
в рабочем прогоне — «ПЗ перенесено на смены по датам: N» и «Шаблонных смен помечено неактивными: 2».
Повторный запуск должен показать «ПЗ с шаблонной сменой: 0».

## Часть 1. Сценарии

### Сценарий 1. Смена выбирается в форме ПЗ (T-075)

**Шаг 1.1.** Под `np` открыть «ПЗ» → «Создать» и посмотреть на поля смены.
- Ожидаемо: вместо списка смен — два поля: «Дата смены» (заполнена сегодняшним числом) и «Смена» («1-я смена (08:00–20:00)» / «2-я смена (20:00–08:00)», выбрана текущая по времени).
- Прислать: текст полей.

**Шаг 1.2.** Заполнить строку ПЗ (РЦ, номенклатура, количество, Оператор), сменить дату смены на вчерашнюю и сохранить черновик.
- Ожидаемо: ПЗ сохраняется, ошибок нет; в списке ПЗ оно есть, в карточке указана выбранная дата смены.
- Прислать: подтверждение и текст шапки карточки ПЗ.

**Шаг 1.3.** Открыть НСИ → «Смены».
- Ожидаемо: экран только для просмотра — нет кнопки «Создать», нет «Редактировать» и «Деактивировать»; в списке есть смена на вчерашнюю дату с числом ПЗ, а шаблонные смены (дата 2000-01-01) помечены неактивными.
- Прислать: текст таблицы смен.

### Сценарий 2. «Производится» считается по дате и номеру (T-075)

**Шаг 2.1.** Под `np` открыть дашборд, период «Текущая смена».
- Ожидаемо: в показатель «Производится» и в виджет «Статусы ПЗ текущей смены по РЦ» попадают только ПЗ смены **сегодняшней** даты и текущего номера; ПЗ, перенесённые бэкфиллом на прошлые даты, в них не видны, но остаются в списке документов.
- Прислать: текст карточки «Производится» и виджета статусов, а также число ПЗ в списке документов.

### Сценарий 3. Правка отправленного Перемещения (T-066)

**Шаг 3.1.** Под `np` открыть любое Перемещение в статусе «Отправлено», нажать «Редактировать» и сменить склад-источник.
- Ожидаемо: подсказка доступного остатка пересчитывается **без** прибавления прежнего резерва: если прежнее количество превышает остаток нового склада, форма сразу подсвечивает превышение, а не пропускает сохранение.
- Прислать: текст подсказки под полем количества до и после смены склада.

### Сценарий 4. Предупреждение при деактивации (T-068)

**Шаг 4.1.** Под `np` открыть НСИ → «Номенклатура», найти позицию, которая используется в открытом ПЗ, и нажать «Деактивировать».
- Ожидаемо: диалог показывает «Незавершённые документы» со списком — короткий идентификатор ПЗ и его статус; деактивация при этом разрешена (кнопка есть). Позицию после проверки **верните в активное состояние**.
- Прислать: текст диалога.

### Сценарий 5. Журнал аудита (наблюдения v2.0.0)

**Шаг 5.1.** Под `np` открыть карточку завершённого ПЗ, изменить **только потребление** (например, на +1) и сохранить; затем посмотреть свежие записи в «Аудите».
- Ожидаемо: в журнале есть запись про изменение потребления, и **нет** записи с одинаковыми старыми и новыми значениями выпуска, брака, причины и остановок. Подпись объекта читается с пробелом: «факт производства <идентификатор>». После проверки верните прежнее значение потребления.
- Прислать: текст двух-трёх свежих строк журнала.

### Сценарий 6. Очистка тестовых данных (T-076)

**Шаг 6.1.** Под `admin` открыть «Данные» и найти пункт меню.
- Ожидаемо: пункт «Данные» есть только у администратора; на экране — группы данных с числом записей и пояснением, что справочники, пользователи и журнал аудита не удаляются.
- Прислать: текст списка групп с числами.

**Шаг 6.2.** Не выбирая групп, ввести слово подтверждения и нажать «Очистить выбранное».
- Ожидаемо: ошибка «Выберите хотя бы одну группу данных», ничего не удаляется.
- Прислать: текст сообщения.

**Шаг 6.3.** Выбрать группу «Уведомления», ввести слово подтверждения и выполнить очистку.
- Ожидаемо: сообщение «Удалено записей: N. Очистка записана в журнал аудита»; после обновления страницы у группы «Уведомления» 0 записей; в «Аудите» появилась запись «очистка данных» с перечнем групп.
- Прислать: текст сообщения и текст строки журнала.

### Сценарий 7. Проверка под ролью без прав администратора

**Шаг 7.1.** Под `ksgp` открыть адрес `/data` вручную.
- Ожидаемо: пункта «Данные» в меню нет; при прямом переходе — экран «Доступ запрещён».
- Прислать: текст меню и текст экрана.
