# Как работать в этом репозитории

Короткая версия для нового человека. Полные правила — `docs/branching_model.md`.

## Первый запуск

```bash
git clone https://github.com/FactoryAll/production.git
cd production
pnpm install
cp .env.example .env          # заполнить POSTGRES_PASSWORD и DATABASE_URL
pnpm db:migrate && pnpm db:seed
pnpm dev                      # http://localhost:3000
```

Нужен PostgreSQL 15+. Значения `.env` спрашиваются у владельца — в репозитории только шаблоны.

## Перед каждым коммитом

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

Все четыре должны быть зелёными. То же самое проверяет CI на каждом пуше и пулл-реквесте.

## Ветки

| Ветка | Для чего | Кто сливает |
|---|---|---|
| `main` | то, что проверено на стенде и выпущено | ответственный за релиз |
| `dev` | работа над новыми модулями | линия разработки |
| `fix/*` | короткоживущие правки, не дольше 2 дней | автор правки |

**Правила, которые нарушать нельзя:**

- миграции базы создаются **только** в `main`;
- в `main` не попадает ничего, что не собрано и не проверено на дев-стенде;
- работа не считается сделанной, пока она не собрана на проде;
- один стенд собирается за раз, сборки не идут параллельно.

## Коммиты

- сообщение по-английски, одна строка, о смысле изменения: `add the timesheet report for operators`;
- один коммит — одно изменение; правки «заодно» не смешиваются с основной;
- каждая правка поведения сопровождается тестом, который падает без неё.

## Секреты

В репозиторий не попадают: `.env`, дампы базы, сертификаты, ключи. Всё это передаётся
через менеджер паролей, а не в переписке и не в issue.
