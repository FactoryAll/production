# Инструменты линии (CLI)

## Где загружать спецификации

Основной путь — **в приложении**: «НСИ → Привязки ГП ↔ Масса» → блок «Загрузить спецификации из 1С»:
выбрать файл → **«Проверить»** (показывает отчёт: что привяжется, что пропущено и почему) →
**«Загрузить привязки»**. Отчёт каждой загрузки сохраняется в журнале и открывается ссылкой
«Показать отчёт последней загрузки». Это путь для НП и АДМ, терминал не нужен.

CLI ниже нужен линии поддержки: посмотреть план без запуска приложения, выгрузить обработанный
набор в CSV, прогнать загрузку из скрипта.

## `bom-plan.ts` — разбор спецификаций 1С и план привязок «ГП → Масса / Туба»

Запуск из каталога `apps/web`:

```bash
DATABASE_URL=postgresql://… node scripts/bom-plan.ts <файл.xlsx> [--csv out.csv]
```

Что делает:

1. читает выгрузку 1С «полная спецификация (BOM)» — свой читатель `.xlsx`, без exceljs
   (выгрузка 1С содержит графику и комментарии, на которых exceljs падает; см. `src/lib/bom-import/xlsx.ts`);
2. оставляет только нужное: из готовой продукции — компоненты **Масса** и **Туба**;
   упаковка, сырьё и спецификации самих Масс/Туб отбрасываются;
3. сверяет с номенклатурой ProdTrack и печатает план: что привяжется, что пропущено и почему,
   какие активные ГП остались без привязки;
4. по `--csv` выгружает обработанный набор (ГП, Масса, норма, Туба) — то, что можно отдать
   на сверку без открытия базы.

Запись в базу намеренно отсутствует: в схеме пока нет поля привязки ГП → Масса
(`docs/gp_mass_binding_analysis.md`). Шаг записи появится вместе с ним.

Каталог `scripts/` исключён из `tsconfig.json` приложения: Node требует расширение `.ts`
в импортах, а сборка Next.js этот каталог не трогает.
